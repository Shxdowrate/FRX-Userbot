# FRX — Fractal Runtime Extension

Telegram-юзербот на [Telethon](https://docs.telethon.dev/) с системой подключаемых модулей,
стационарным ботом на [aiogram 3](https://docs.aiogram.dev/) и локальным сайтом управления.
Модуль FRX — один `.py`-файл: команды, наблюдатели за сообщениями, циклы, инлайн-формы с кнопками,
настройки, страницы сайта. Всё, что видит пользователь (`.help`, `.config`, `.update`, нейросеть,
сайт), — тоже модули.

> **Перед установкой.** Юзербот работает от имени вашего личного аккаунта Telegram. Автоматизация
> пользовательских аккаунтов — серая зона правил Telegram: аккаунт могут ограничить или заблокировать,
> особенно за массовые рассылки, флуд и спам. FRX умеет исполнять произвольный код (`.eval`, модули,
> инструменты нейросети) — устанавливайте только те модули, код которых прочитали. Вы используете FRX
> на свой риск, см. [`LICENSE`](LICENSE) и [`SECURITY.md`](SECURITY.md).

**Что умеет FRX**

- **Модули на лету.** `.loadmod` ответом на файл — превью и установка без перезапуска; выгрузка,
  восстановление, перезагрузка, отправка файла модуля в чат.
- **Инлайн-формы.** Сообщение «via @ваш_бот» с кнопками, полями ввода и страницами, которым управляет
  юзербот, — в любом чате, где вы пишете.
- **Стационарный бот.** Создаётся и настраивается сам через @BotFather; модули могут объявлять его команды,
  наблюдателей и инлайн-функции рядом с командами юзербота.
- **Настройки модулей** (`.config`) — типизированные, с проверкой значений, в чате и на сайте.
- **Мультиаккаунт** — несколько аккаунтов Telegram, переключение на лету.
- **Локальный сайт `.web`**: конфиги, модули, редактор модулей FRX WebIDE с подсветкой и историей,
  песочница Sandbox, визуальный конструктор Lab, Emulate (запуск команд любого модуля прямо на сайте),
  файлы, логи, аккаунты, BotChat (переписка от имени бота), нейросети.
- **Нейросети (NeuroDash).** Любой провайдер — Ollama, OpenAI, Anthropic, DeepSeek, GigaChat, OpenRouter,
  Groq, xAI, Gemini, Mistral, свой сервер; учёт токенов и лимиты; 45 инструментов-файлов (поиск в сети,
  Telegram, файлы, память, код) с подтверждением опасных действий.
- **SystemKeeper.** Перезапуск, обновление из zip или GitHub с резервной копией и автоматическим откатом,
  бэкапы данных, гибернация при пропаже сети.
- **Всё личное — в одной папке `user/`.** Код проекта не содержит ваших данных: его можно обновлять,
  копировать и публиковать.

Этот README — полный справочник: сначала для пользователя (установка, команды, сайт, нейросети),
затем для автора модулей (устройство ядра и весь API). История изменений — в [`CHANGELOG.md`](CHANGELOG.md).

## 1. Что такое FRX и из чего он состоит

FRX — это **движок**, к которому подключаются модули. Сам по себе движок ничего не показывает: даже
`.help`, `.loadmod` и `.ping` — обычные модули из папки `modules/builtin/`, которые загружаются при
каждом старте.

В работе участвуют три процесса-сущности:

1. **SystemKeeper** (`frx_systemkeeper.py`) — «материнский» процесс. Его вы и запускаете. Он запускает
   юзербота подпроцессом, перезапускает его, применяет обновления и восстановление бэкапов, держит порт
   сайта, пока юзербот перезагружается, и переводит юзербота в гибернацию, если пропала сеть. Написан
   только на стандартной библиотеке и не зависит от `core/`, поэтому работает даже при сломанном ядре.
2. **Юзербот** — объект `Core` (`core/engine.py`) поверх `telethon.TelegramClient`. Работает от лица вашего
   аккаунта, видит все сообщения во всех ваших чатах и выполняет команды, которые **вы сами** пишете
   (только исходящие сообщения).
3. **Стационарный бот** — обычный бот на aiogram (`aiobot/bot.py`). Он нужен для того, что не умеет
   пользовательский аккаунт: инлайн-формы с кнопками, сообщения и логи вам в личку, BotChat. Бот
   необязателен — без него юзербот работает, но формы недоступны (команды с формами переходят на
   текстовый вид или просят токен).

Юзербот и бот живут в одном event loop (`main.py`) и управляются одним объектом `Core`: юзербот
инициирует действие (например, «показать форму»), бот его выполняет и возвращает клики обратно в модуль.

## 2. Установка и первый запуск

**Нужно:** Python 3.10 или новее, аккаунт Telegram, `api_id` и `api_hash` с
<https://my.telegram.org> (раздел *API development tools*). Для кружков и голосовых в BotChat нужен
ffmpeg — он ставится вместе с пакетом `imageio-ffmpeg` или берётся из `PATH`.

FRX ставится одинаково на сервер и на свой компьютер — скачайте проект (`git clone` или архив) и запустите
установщик в его папке:

| Где | Установка | Запуск потом |
|---|---|---|
| Linux (сервер, VPS, Raspberry Pi), macOS | `sh install.sh` | сам (служба) или `./start.sh` |
| Windows | `install.bat` (двойной клик) | сам (автозагрузка) или `start.bat` |
| Docker (любая ОС) | `docker compose run --rm -e FRX_SETUP_ONLY=1 frx` | `docker compose up -d` |

Установщик (`frx_setup.py`) делает всё по шагам и объясняет каждый:

1. **Окружение** — `.venv` в папке проекта и зависимости из `requirements.txt`. Нет Python 3.10+ или модуля
   `venv` — подскажет команду установки для вашей системы (apt, dnf, pacman, apk, brew, python.org).
2. **Первый вход в Telegram** прямо в этом окне: `api_id`/`api_hash`, номер, код, облачный пароль. FRX
   запускается в режиме настройки (`FRX_SETUP_ONLY=1`): после входа сам создаёт стационарного бота и
   останавливается.
3. **Автозапуск** (спросит): Linux — служба systemd `frx` (системная через sudo или пользовательская +
   `loginctl enable-linger`, чтобы работала после выхода из SSH), перезапуск при падении, `.exit` останавливает
   насовсем; macOS — LaunchAgent; Windows — запуск при входе в систему свёрнутым окном. Нет systemd (контейнер,
   WSL без systemd) — подскажет `tmux new -s frx ./start.sh`.
4. **Как открыть сайт** — готовые адреса и команда SSH-туннеля с IP этой машины ([раздел 12](#12-локальный-сайт-web)).

Ключи установщика: `--yes` (на всё «да»), `--no-service`, `--no-login` (сессия уже есть, например из бэкапа),
`--remove-service` (убрать автозапуск). Управление службой Linux: `sudo systemctl status|restart|stop frx`,
логи — `sudo journalctl -u frx -f` (для пользовательской службы — `systemctl --user …`, `journalctl --user …`).

**Docker.** Образ содержит только Python и зависимости, а код и данные лежат на хосте (`./` → `/app`), поэтому
`.update`, бэкапы и `pack` работают как обычно; пересобрать образ (`docker compose build`) нужно, только если
обновление поменяло `requirements.txt`. Сайт публикуется только на `127.0.0.1` хоста; `restart: on-failure` —
`.exit` останавливает насовсем. Первый вход — командой из таблицы, затем `docker compose up -d`, логи —
`docker compose logs -f`.

Вручную, без установщика:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate      Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python frx_systemkeeper.py
```

Запускается **всегда `frx_systemkeeper.py`**. `main.py` без keeper'а сразу завершается с подсказкой —
перезапуск и обновление невозможны без «родителя», который поднимет процесс заново. В IDE назначьте
файлом запуска `frx_systemkeeper.py`.

**FRX разворачивается сам.** В репозитории только код — ни папки данных, ни конфига, ни модулей
пользователя. При первом запуске keeper создаёт папку `user/` со всей структурой (`config.json`, `data/`,
`modules/`, `assets/`, раздел 3), а ядро раскладывает туда базу, сессию, инструменты нейросети и остальное по
мере надобности.

**Первый запуск целиком проходит в терминале** (так надёжнее, если юзербот стоит на сервере):

1. Нет `user/config.json` или в нём пустые `api_id`/`api_hash` — FRX спрашивает их в консоли,
   проверяет формат и сохраняет в `user/config.json`.
2. Telethon спрашивает номер телефона, код из Telegram и, если включён, пароль двухэтапной защиты.
   Сессия сохраняется в `user/data/frx_session.session` — дальше вход не нужен.
3. Загружаются встроенные и ваши модули, в терминале: `Юзербот запущен. Загружено модулей: N`.
4. Если токена стационарного бота нет, модуль **Startup** сам создаёт бота через диалог с @BotFather от
   вашего имени, включает ему инлайн-режим и инлайн-фидбэк 100 %, записывает токен в `user/config.json`,
   и бот сразу запускается. Ничего настраивать руками не нужно (подробнее — [раздел 9](#9-стационарный-бот)).

Если stdin закрыт (запуск без терминала) и данных для входа нет — процесс завершается с кодом 78,
keeper его не перезапускает.

**После запуска** напишите в любом чате `.help` — список модулей и команд; `.info` — версия и система;
`.web` — ссылка на локальный сайт.

**Обновление** — команда `.update` (ответом на zip-архив или из GitHub), см. [раздел 8](#8-systemkeeper-перезапуск-обновление-бэкапы-гибернация).
Если вы держите FRX в git, обычный `git pull` и `.restart` тоже работают: ваши данные в `user/` и в
репозиторий не попадают.

**Свернуть перед публикацией.** Развернули FRX, поработали, поправили код — и хотите выложить проект в git
или отдать архивом? Запустите `pack.bat` (Windows) или `sh pack.sh` (Linux, macOS) в корне проекта (или
`python frx_pack.py`). Скрипт:

1. проверяет, что юзербот из этой папки не запущен;
2. ищет в коде ваше личное — ваши `api_id`/`api_hash`, токены, id, `@username` и номера аккаунтов (значения
   берёт из вашей же `user/`), а также типовые секреты: токен бота, StringSession, ключи API, номера телефонов —
   и показывает файл и строку;
3. если проект — git-репозиторий, проверяет, не отслеживает ли git что-то личное (`user/`, `*.session`, `config.json`);
4. показывает, что удалит, и после подтверждения (`да`) удаляет: папку `user/` целиком (конфиг, БД, сессии,
   аккаунты, бэкапы, ваши модули и ассеты), старые `config.json` / `data/` / `modules/loaded/`, `*.session`,
   `__pycache__`, `*.pyc`, логи;
5. пересоздаёт `frx_manifest.json` — список файлов релиза (раздел 8, «Что обновляется»).

Ваши правки кода остаются — сворачиваются только личные данные. Ключи: `--dry-run` (только показать),
`--yes` (без вопроса), `--zip` (собрать `dist/FRX_<версия>.zip` для `.update`), `--force` (сворачивать, даже
если юзербот вроде бы запущен). Код выхода `2` — свернуто, но в коде или git осталось личное: не публикуйте,
пока не исправите. Следующий `python frx_systemkeeper.py` развернёт FRX заново, с вопросами первого запуска.

## 3. Папка user/ — ваши данные

Всё, что принадлежит конкретному владельцу юзербота, лежит в одной папке `user/` рядом с `main.py`. В
репозитории её нет — keeper создаёт её при первом запуске (вместе с `README.txt` — памяткой, что здесь лежит).
Код проекта (`core/`, `aiobot/`, `modules/builtin/`, `assets/` и файлы в корне) одинаков у всех и
обновляется командой `.update`; папку `user/` обновление не трогает никогда.

```
user/
├── config.json              api_id, api_hash, токен бота и параметры запуска (раздел 4)
├── modules/                 ваши модули (.loadmod, WebIDE, Lab или просто положите .py)
│   └── unloaded/            выгруженные модули (.unloadmod); вернуть — .restoremods
├── assets/                  ваши файлы-ассеты (сайт → files); перекрывают стоковые из assets/
└── data/
    ├── database.json        БД модулей: настройки (.config), данные db.*, префикс, служебные ключи
    ├── frx_session.session  сессия Telethon первого аккаунта
    ├── accounts.json        мультиаккаунт: сессии (StringSession), теги, сведения профилей
    ├── files/               файлы реестра files (скачанные командами, созданные модулями)
    ├── ai_files/            песочница файлов нейросети (инструменты read_file/write_file…)
    ├── neuro/               нейросети: providers.json (ключи!), usage.json, settings.json, tools/…
    ├── botchat/             история BotChat: store.json, media/, avatars/
    ├── webide/history/      история изменений модулей в WebIDE
    ├── webide/drafts/       несохранённые правки редактора и Lab (черновики)
    ├── sandbox/             участники и чаты, созданные в Sandbox
    ├── emulate_uploads/     файлы, приложенные к командам в Emulate (временные)
    ├── backup/              резервные копии keeper'а (код перед обновлением, данные)
    └── keeper/              служебные файлы SystemKeeper (заявки, журнал, состояние сайта)
```

> **Никогда не публикуйте и не пересылайте `user/`.** Сессии в `frx_session.session` и `accounts.json`
> дают вход в ваши аккаунты без пароля и кода, `config.json` содержит токен бота, `neuro/providers.json` —
> ключи нейросетей открытым текстом. `.gitignore` проекта исключает `user/` целиком. Что делать при
> утечке — в [`SECURITY.md`](SECURITY.md).

**Другое место для данных.** Переменная окружения `FRX_USER_DIR` задаёт папку пользователя —
абсолютный путь или путь относительно папки проекта. Так на одном коде можно держать несколько
юзерботов:

```bash
FRX_USER_DIR=/srv/frx/alice python frx_systemkeeper.py
```

**Переезд со старой раскладки.** Если в корне проекта лежат `config.json`, `data/` и
`modules/loaded/` (так FRX хранил данные раньше), keeper при запуске сам переносит их в `user/`
(`config.json` → `user/config.json`, `data/` → `user/data/`, `modules/loaded/` → `user/modules/`) и
переписывает пути в реестре файлов. Ошибка на середине — всё уже перенесённое возвращается на место, и
юзербот продолжает работать по-старому. Пока перенос не выполнен (например, сразу после `.update` со
старой версии, когда в памяти ещё работает прежний keeper), все пути указывают на старые места, а в
терминале при каждом запуске есть подсказка: перезапустите `python frx_systemkeeper.py`. Если `user/`
уже есть, а старые файлы тоже остались, keeper их не трогает и пишет предупреждение — перенесите нужное
вручную.

Все пути в коде берутся из одного места — `core/paths.py` (`CONFIG_PATH`, `DATA_DIR`, `MODULES_DIR`,
`UNLOADED_DIR`, `USER_ASSETS_DIR`, `FILES_DIR`, `KEEPER_DIR`, `BACKUP_DIR`, …). Модулям, которым нужен
путь к данным, тоже стоит импортировать его оттуда: `from core.paths import DATA_DIR`.

## 4. user/config.json — все поля

Создаётся при первом запуске (см. раздел 2) или вручную по образцу `config.example.json`:

```json
{
  "api_id": 0,
  "api_hash": "",
  "aiogram_token": "",
  "prefix": ".",
  "web_port": 8878,
  "web_sentinel": true,
  "web_hosts": [],
  "hibernate_probe_seconds": 7,
  "hibernate_after_seconds": 30
}
```

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `api_id` | int | — (обязательно) | ID приложения Telegram с https://my.telegram.org |
| `api_hash` | str | — (обязательно) | hash приложения Telegram оттуда же |
| `aiogram_token` | str | `""` | Токен стационарного бота. Пусто — Startup создаст бота сам и впишет сюда токен. Если токен есть, но бот удалён или токен отозван, Startup пересоздаст бота |
| `prefix` | str | `.` | Стартовый префикс команд. После первого запуска действующий префикс хранится в БД (`core:prefix`, `engine.edit_prefix()`); значение отсюда — только значение по умолчанию |
| `db_path` | str | `user/data/database.json` | Путь к БД. Обычно не нужен. Относительный путь вида `data/...` считается относительно `user/`, другой относительный — относительно папки проекта |
| `web_port` | int | `8878` | Порт сайта `.web`. Занят — берётся следующий, до 20 попыток |
| `web_sentinel` | bool | `true` | «Сторож» сайта: пока сайт выключен, keeper слушает его порт, и первый заход на адрес сам поднимает сайт ([раздел 12](#12-локальный-сайт-web)). `false` — выключить |
| `web_hosts` | list | `[]` | Дополнительные имена хостов, с которыми можно открывать сайт — для своего домена за reverse-proxy с HTTPS (например `["frx.example.com"]`). Локальные адреса и адрес публичного туннеля разрешены всегда |
| `hibernate_after_seconds` | number | `30` (минимум 10) | Сколько секунд клиент Telegram может быть отключён, прежде чем юзербот проверит сеть и уйдёт в гибернацию |
| `hibernate_probe_seconds` | number | `7` (2…600) | Как часто keeper в гибернации проверяет связь с Telegram |

## 6. Команды — краткий справочник

Команды пишутся **с вашего аккаунта** в любом чате с префиксом (по умолчанию `.`). Чужие сообщения
командами не считаются — кроме людей, которым вы выдали доступ ([раздел 11](#11-доступ-для-других-людей-и-алиасы)). Регистр команды не важен. Большинство команд отвечают инлайн-формой от
стационарного бота; без бота они переходят на текстовый вид или подтверждение словом `yes`.

| Команда | Модуль | Что делает |
|---|---|---|
| `.help` / `.h` `[модуль или команда]` | Helper | без аргумента — список модулей; с модулем — его карточка; с командой — справка по команде |
| `.modules` / `.mods` | Helper | список модулей (встроенные и загруженные) с кнопкой выбора и карточками |
| `.checkmodule` / `.checkmod` | Helper | ответом на `.py`-файл: статическая проверка модуля до загрузки |
| `.checkall` | Helper | проверка всех загруженных модулей на типовые проблемы |
| `.loadmod` / `.lm` | Loader | ответом на `.py`/`.txt`: превью модуля и установка (или обновление) после подтверждения |
| `.unloadmod` / `.ulm` `<модуль>` | Loader | выгрузить модуль; файл уезжает в `user/modules/unloaded/` |
| `.reloadmod` / `.rm` `<модуль>` | Loader | перечитать модуль с диска и перезагрузить |
| `.restoremods` / `.rsm` `[модуль]` | Loader | список выгруженных модулей: восстановить или удалить навсегда |
| `.sendmodule` / `.sm` `<модуль>` | Loader | прислать файл модуля в чат (встроенные тоже) |
| `.config` / `.cfg` `[модуль]` | Config | настройки модулей: группа → модуль → значение (инлайн) |
| `.confighelp` / `.cfghelp` | Config | подсказка по `.config` |
| `.info` | Info | версия, префикс, модули, аккаунты, аптайм, система; конфиденциальное — по кнопке |
| `.accounts` / `.acc` | AccountManager | аккаунты: список, переключение, добавление (телефон → код → 2FA), удаление |
| `.eval` / `.ev` / `.exec` `<код>` | Eval | выполнить Python-код (аргументом, ответом на сообщение или на `.py`/`.txt`) |
| `.ping` | ping | задержка ответа, мс |
| `.dping` | ping | задержка с разбивкой по этапам |
| `.forms` | InlineStuff | активные инлайн-формы |
| `.closeform` `<id>` | InlineStuff | закрыть форму по первым символам её id |
| `.logs` / `.logshelp` | Logging | справка по пересылке логов в ЛС |
| `.changelog` / `.cl` `[версия \| list]` | Changelog | что нового: запись версии, выбор версии кнопками, `list` — список |
| `.restart` / `.rs` | SystemKeeper | перезапустить юзербот |
| `.update` / `.upd` `[git] [yes]` | SystemKeeper | обновить FRX: ответом на `.zip` или `.update git` из GitHub; `yes` — без подтверждения |
| `.sk` / `.systemkeeper` | SystemKeeper | статус keeper'а, настройки GitHub, резервные копии |
| `.exit` | SystemKeeper | бэкап данных в ЛС от бота и полное выключение (без перезапуска) |
| `.createbackup` | Backup | бэкап папки `user/` файлом в ЛС от бота |
| `.restorebackup` `[yes]` | Backup | ответом на файл бэкапа — восстановить данные |
| `.web` / `.site` `[stop \| tunnel on\|off\|new \| logout]` | Web | поднять сайт и прислать ссылки; `stop` — выключить; `tunnel` — публичный адрес; `logout` — выйти на всех устройствах |
| `.botchat` / `.bc` `[clear]` | BotChat | состояние истории BotChat; `clear` — стереть историю на сайте |
| `.neuro` / `.n` | NeuroDash | чат с нейросетью |
| `.neurotool` / `.nt` `[list \| add \| send \| sendall \| del \| on \| off \| help]` | NeuroDash | инструменты нейросети |
| `.access` / `.acs` `[пользователь \| grant \| revoke \| check \| list \| classes]` | Access | доступ других людей к командам юзербота; ответом на сообщение — меню этого человека |
| `.alias` `[команда [аргументы] новое_имя]` | Aliases | алиас команды; без аргументов — список |
| `.unalias` `<имя>` | Aliases | удалить алиас |

**Команды стационарного бота** (пишутся боту в личку): `/start` — доступно всем, `/status` — только
владельцу (число загруженных модулей). Модули могут добавлять свои (`import bot`, [раздел 28](#28-стационарный-бот-в-модулях-import-bot-inline_function-enginebot)).

**Префикс** хранится в БД. Отдельной команды смены префикса во встроенных модулях нет — есть API
`engine.edit_prefix()`; поменять можно, например, через `.eval await engine.edit_prefix('!')`.

## 7. Встроенные модули

Встроенные модули лежат в `modules/builtin/`, загружаются при каждом старте раньше ваших и
обновляются вместе с кодом. Выгрузить или удалить встроенный модуль нельзя. Их настройки меняются через
`.config <модуль>` или на сайте (вкладка «конфиги»).

### Helper — `.help`, `.modules`, проверка модулей

- **`.modules`** — текст со списком модулей в двух разделах, «встроенные» и «загруженные», и одна кнопка
  «Выбрать модуль». Она открывает экран выбора по 7 модулей на странице (встроенные помечены ▣, загруженные — ▤)
  с навигацией ◂ N/M ▸ внизу. Модуль открывает **карточку**: название, ID, версия, автор, описание, все команды
  с алиасами и описаниями, обработчики. Кнопки карточки:
  - «Открыть конфиг» — только если у модуля есть настройки; открывает тот же `.config <модуль>`;
  - «Отправить модуль» — файл модуля в чат (как `.sendmodule`);
  - «Удалить модуль» — с подтверждением, удаляет файл окончательно (мягкая выгрузка — `.unloadmod`);
    у встроенных модулей кнопки нет;
  - «Назад» — к той странице выбора, где стоит модуль.
- **`.help <модуль>`** (по `MODULE_NAME` или отображаемому имени, без учёта регистра) — сразу карточка.
  **`.help <команда>`** — справка по команде или алиасу. Не нашлось — подсказка с похожими модулями.
- Без стационарного бота всё то же выводится обычным текстом.
- **`.checkmodule`** (ответом на `.py`-файл) разбирает файл через `ast`, **не исполняя код**, и делит
  проблемы на ошибки и предупреждения: синтаксис, наличие и уникальность `MODULE_NAME`, метаданные,
  отсутствие декораторов и функций, хэндлеры без `async def` и без докстрингов, `db.*` без `import db`,
  нет `import engine`/`decorators`/`visual`, нет `try/except` (рекомендация). **`.checkall`** — то же
  по всем загруженным модулям.

### Loader — установка и выгрузка модулей

- **`.loadmod`** ответом на `.py` или `.txt` (регистр расширения не важен). Файл сначала разбирается
  статически и показывается **превью**: название, `MODULE_NAME`, версия, автор, описание, найденные команды —
  с кнопками «Загрузить»/«Отмена». Модуль исполняется только после подтверждения и сохраняется как
  `user/modules/<MODULE_NAME>.py` (имя присланного файла значения не имеет, `.txt` становится `.py`).
  - Модуль с таким `MODULE_NAME` уже загружен и **версия та же** — отказ «уже загружен».
  - **Версия другая** — это обновление: превью показывает «версия X → Y» и кнопку «Обновить»; старая
    версия выгружается без архивации и тут же заменяется новой.
- **`.unloadmod <модуль>`** — модуль выгружается, а его файл **переносится** в `user/modules/unloaded/`:
  автозагрузка его больше не видит, выгрузка переживает перезапуск.
- **`.restoremods`** — список выгруженных → «Выбрать модуль» → страница по 7 → карточка с кнопками
  «Восстановить» и «Удалить навсегда» (с подтверждением). `.restoremods <имя>` открывает карточку сразу.
  Без бота: `.restoremods` — текстовый список, `.restoremods <имя>` — сразу восстанавливает.
- **`.reloadmod <модуль>`** — перечитать файл с диска (после ручной правки).
- **`.sendmodule <модуль>`** — файл модуля в чат с подписью (название, ID, версия, автор, описание).

### Config — настройки модулей

`.config` открывает инлайн-меню: «встроенные / загруженные» → модуль → настройка → действие. Типы и
действия:

| Тип | Действия |
|---|---|
| `str`, `int`, `float` | ввести новое значение (кнопка-поле ввода), проверка `valid=` (границы, длина) |
| `bool` | переключить |
| `list` | добавить элемент, удалить элемент |
| `choice` | выбрать один вариант из списка |
| `choices` | отметить несколько вариантов (снять последний нельзя) |

У каждой настройки есть «Сбросить» — сначала экран подтверждения (текущее → по умолчанию), затем сброс к
значению, с которым настройка создана. `.config <модуль>` сразу открывает настройки модуля. Нужен
стационарный бот. Те же настройки есть на сайте (вкладка «конфиги»). В модуле Config есть набор
демонстрационных настроек `test_config_*` всех типов — на них удобно посмотреть, как выглядит каждый тип.

### Info — `.info`

Сводка: версия ядра, префикс, число модулей и аккаунтов, аптайм; раздел «Система» — Python, ОС, архитектура.
Над сообщением — медиа (настройка `media`). Кнопка «Открыть конфиденциальные сведения» (нажать может только
владелец) показывает активный аккаунт (номер, id, имя), список аккаунтов, замаскированный токен бота, хост,
рабочую папку, `api_id` и замаскированный `api_hash`.

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `media` | `experience_1` | `experience_1` — встроенная анимация FRX (`assets/experience/experience_1.mp4`), `none` — без медиа, или ссылка / путь к своей картинке (`.jpg`/`.png`/`.webp`) или анимации (`.mp4`/`.gif`/`.webm`) |

### AccountManager — `.accounts`

Инлайн-меню мультиаккаунта: список аккаунтов (имя, id, номер — скрыт или показан), кнопки «Номера»
(показать/скрыть), «Добавить аккаунт», «Переключить аккаунт», «Удалить аккаунт» (с подтверждением).
Добавление — мастер прямо в форме: «Ввести номер» → «Ввести код» → при включённой 2FA «Ввести пароль»;
ошибки Telegram (неверный номер, код истёк, флуд-ожидание) объясняются по-человечески, введённый пароль в
чат не выводится. Подробности — [раздел 10](#10-мультиаккаунт).

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `show_phone_number` | `false` | показывать номера телефонов в меню |
| `phone_prefix_show` | `3` | сколько первых цифр видно у скрытого номера |

### Eval — `.eval`

Выполняет любой Python-код, в том числе с `await`. Код — аргументом, ответом на сообщение с кодом или
ответом на `.py`/`.txt`-файл. Если в коде есть `return` на верхнем уровне — результатом будет его значение;
иначе — значение последнего выражения. Ответ — форма с блоками «код / вывод / результат» и кнопками
«Редактировать» (поле ввода, предзаполненное текущим кодом), «Повторить», «В .py файл».

Готовые имена внутри кода: `event`, `engine`, `decorators`, `visual`, `db`, `cache`, `waiters`, `files`,
`accounts`, `time_utils`, `client` (= `engine.client`), `asyncio`, `os`, `sys`, `re`, `json`; любые другие
`import` тоже работают.

> `.eval` — **без каких-либо ограничений**: полный доступ к аккаунту, файлам, сети и ОС. Он срабатывает

## 8. SystemKeeper: перезапуск, обновление, бэкапы, гибернация

### Как это устроено

```
python frx_systemkeeper.py           единственная точка запуска; только стандартная библиотека
        │  подпроцесс: python -u main.py  (FRX_KEEPER=1, общий терминал)
        ▼
     main.py → Core (Telethon) + стационарный бот (aiogram)
        │  модуль пишет user/data/keeper/request.json и завершает процесс кодом 42 / 43
        ▼
keeper (main.py остановлен): резервная копия → замена файлов → pip → запуск → проверка → откат при неудаче
```

Файлы заменяются, **пока `main.py` не запущен** — ничего не занято (важно на Windows). Пакет обновления
сначала полностью проверяется модулем, пока юзербот ещё работает, и лишь потом передаётся keeper'у.

**Коды выхода `main.py`:**

| Код | Значение | Что делает keeper |
|---|---|---|
| `0` | обычная остановка (`.exit`, Ctrl+C) | завершается сам |
| `42` | перезапуск (`.restart`) | запускает `main.py` заново |
| `43` | применить заявку (`update` / `restore`) | выполняет заявку и запускает `main.py` |
| `78` | ошибка конфигурации (нет данных для входа) | завершается без повторов |
| `79` | нет связи с Telegram | гибернация (ниже) |
| другой | аварийное завершение | политика падений (ниже) |

**Политика падений.** Упал сам — keeper пробует перезапустить **один раз** (через 3 с). «Запустился
полноценно» = `main.py` записал `ready.json` (ядро и бот подняты) и проработал 60 секунд; тогда счётчик
сбрасывается. Второе падение подряд до этого момента — keeper останавливается.

### Перезапуск и выключение

- **`.restart`** — после перезапуска исходное сообщение превращается в «Юзербот перезагружен · N сек».
- **`.exit`** — делает бэкап данных (файлом в ЛС от бота) и выключает юзербот вместе с keeper'ом.
  Включить обратно — снова `python frx_systemkeeper.py`.

### Обновление

- **`.update`** ответом на `.zip`: в корне архива должна быть папка `FRX/` (`FRX/main.py`, `FRX/core/…`).
- **`.update git`**: архив ветки скачивается с GitHub (настройки `github_repo`, `github_branch`,
  `github_token` в `.config systemkeeper`). Используется `api.github.com` и стандартная библиотека — git не
  нужен; токен отправляется только на `api.github.com`. Автопроверки обновлений нет: команда сама сравнивает
  версии.
- Показывается превью: версии «было → станет», нужно ли обновлять зависимости, списки добавленных (`+`),
  изменённых (`~`) и удалённых (`−`) файлов, — и обновление ставится только после подтверждения.
  `yes` в команде — без подтверждения; без стационарного бота подтверждение только словом `yes`.

**Проверки перед установкой:** структура архива; обязательные файлы (`main.py`, `frx_systemkeeper.py`,
`requirements.txt`, `core/engine.py`, `aiobot/bot.py`, `modules/builtin/SystemKeeper.py`); версия в
`core/engine.py` архива **строго новее** установленной (та же и более старая не ставятся); все `.py`
компилируются; пути в архиве без `..` и абсолютных (защита от zip-slip); размер после распаковки ограничен
(500 МБ, скачивание — 200 МБ).

**Что обновляется — по манифесту.** Ставятся **все** файлы кода из архива — в том числе новые папки и
файлы в корне, которых в старой версии не было. Кодом не считаются и не ставятся никогда: папка `user/`
(даже если она есть в архиве), старые `config.json` / `data/` / `modules/loaded/`, `.git`, виртуальные
окружения (`.venv`, `venv`, `env`), `__pycache__`, `*.pyc`, логи, `dist/`, `build/`.

После установки keeper пишет `frx_manifest.json` — список файлов установленной версии с хешами. При
следующем обновлении файл, который был в манифесте старой версии и которого нет в новой, **удаляется**
(пустые папки — тоже). Файлы, которых нет в манифесте, — ваши собственные файлы в корне проекта, файлы,
добавленные в `assets/`, — не трогаются никогда. В превью удаляемые файлы показаны со знаком `−`.
Установка без манифеста (из старого архива) считает «старым кодом» прежний набор: `core/`, `aiobot/`,
`modules/builtin/`, `examples/` и файлы корня проекта; `assets/` в этом случае только дополняется.

**Резервная копия и откат.** Перед заменой keeper пишет `user/data/backup/code_<время>_v<версия>.zip`
(хранятся последние 3): код установки, всё, что архив перезапишет, манифест и список файлов, которые
обновление создаст (при откате они удаляются). Если `requirements.txt` изменился — keeper сам выполняет
`pip install -r requirements.txt`. Если новая версия упала до `ready.json` или в первые 60 секунд после
него — keeper возвращает прежние файлы и запускает прежнюю версию. Пока идёт замена, ведётся
`journal.json`: если процесс прервали на середине (например, пропало питание), при следующем запуске keeper
сам откатит изменения. Новый `frx_systemkeeper.py` начинает работать только со следующего полного запуска;
если он окажется сломан логически, верните его вручную из `user/data/backup/code_*.zip`.

**Уведомления.** Сообщение с командой после перезапуска правится: «FRX обновлён: X → Y» или «Обновление
не удалось… выполнен откат». Подробности (источник, время, резервная копия, списки файлов, вывод pip,
причина неудачи) приходят в ЛС от бота (настройка `notify_details`, канал — как у Logging) и пишутся в
терминал.

### Бэкапы данных

- **`.createbackup`** собирает `frx_backup_v<версия>_<время>.zip` — всю папку `user/`: `config.json`,
  `data/` (кроме `backup/`, `keeper/` и кэша файлов BotChat), `modules/`, `assets/`. Живые сессии Telethon
  копируются целостно (SQLite backup API). Файл приходит **в ЛС от стационарного бота**; если бот не может
  написать (нет диалога, бот в ЧС), юзербот сам снимает его с ЧС, пишет ему `/start` и повторяет. Лимит Bot
  API — 50 МБ; больше — команда попросит уменьшить `user/data/files`.
  **В бэкапе лежат сессии и токен — это полный доступ к аккаунту, не пересылайте его.**
- **`.restorebackup`** ответом на такой файл: архив проверяется (`manifest.json`, пути), после
  подтверждения юзербот останавливается, keeper делает страховую копию текущих данных
  (`user/data/backup/userdata_prerestore_*.zip`), заменяет `config.json`, `data/` (кроме `backup/` и `keeper/`),
  `modules/` и `assets/` содержимым бэкапа и запускает юзербот. Не стартовал — данные возвращаются из
  страховой копии. Бэкапы старого формата (с `modules/loaded/`) тоже принимаются.
- `.exit` и уход в гибернацию тоже делают бэкап (`user/data/backup/offline_*.zip`, последние 3).

### Гибернация и сторож сайта

- Клиент Telegram отключён дольше `hibernate_after_seconds` и серверы Telegram недоступны — юзербот
  завершается с кодом 79. Keeper делает резервную копию данных и раз в `hibernate_probe_seconds` проверяет
  связь; как только сеть вернулась — запускает юзербот сам.
- Пока сайт выключен (и при включённом `web_sentinel`), keeper держит порт сайта лёгким «сторожем»: заход
  на адрес сайта показывает «Запускаю сайт FRX…» и поднимает настоящий сайт. Во время гибернации сторож
  показывает «Нет связи с Telegram».
- При `.restart`/`.update`/`.restorebackup` сайт не пропадает: keeper держит порт заглушкой «юзербот спит»
  (не дольше 15 минут), новый процесс забирает порт обратно.

### Протокол keeper ↔ main (`user/data/keeper/`)

| Файл | Кто пишет | Содержимое |
|---|---|---|
| `request.json` | модуль | `{action: restart \| update \| restore, notify: {chat_id, message_id}, meta}` |
| `result.json` | keeper | итог: `ok`, `rolled_back`, `error`, `from`/`to`, `added`/`changed`/`removed`, `pip`, `backup` |
| `ready.json` | `main.py` | `{pid, version, time}` — «запущен полностью» |
| `journal.json` | keeper | идёт замена файлов (для отката при обрыве) |
| `staging/`, `restore/` | модуль | проверенный пакет обновления / распакованный бэкап |
| `incoming/`, `tmp/` | модуль | временные файлы |
| `web_state.json`, `web_takeover`, `web_wake`, `web_sentinel.json` | main ↔ keeper | порт сайта при перезапуске, сторож |
| `tunnel_request.json`, `tunnel.json` | main ↔ keeper | включить публичный туннель / его адрес и состояние |
| `keeper.pid` | keeper | pid работающего keeper'а (`pack` не сворачивает запущенный FRX) |
| `keeper.log` | keeper | журнал действий |

Функции keeper'а доступны встроенным модулям как `import frx_systemkeeper as keeper` (`prepare_update`,
`download_github`, `make_user_backup`, `prepare_restore`, `write_request`, …) — проверка, бэкап и
восстановление живут в одном файле.

## 9. Стационарный бот

Стационарный бот нужен для инлайн-форм, логов и бэкапов в ЛС, BotChat. Модуль **Startup** делает так,
чтобы он просто работал:

1. **Нет токена** — создаёт бота через диалог с @BotFather от вашего имени: имя профиля
   `[FRX] Userbot of <ваше имя>`, username `frx_<имя>_userbot`, при занятости — `frx<10..99>_<имя>_userbot`
   (до 20 попыток). Токен пишется в `user/config.json` и в `engine.config`, и `main.py` тут же поднимает бота.
2. **Токен есть, но бот недоступен** (удалён в @BotFather, токен отозван) — бот пересоздаётся тем же
   способом, вам в «Избранное» приходит уведомление.
3. **Инлайн-режим и инлайн-фидбэк.** Протокол форм требует у бота `/setinline` и `/setinlinefeedback 100%`.
   Startup проверяет это при каждом запуске (`getMe().supports_inline_queries` и метка в БД) и при
   необходимости сам проводит диалог с @BotFather (плейсхолдер `FRX`, фидбэк 100 %). Ошибка настройки
   запуск не роняет — попытка повторится при следующем старте.
4. **Бот в чёрном списке** вашего аккаунта — сам снимает его оттуда и пишет `/start`.
5. Если текущий аккаунт ещё не писал боту, юзербот отправляет ему `/start` (иначе бот не смог бы написать
   вам первым — ограничение Bot API). То же — при переключении на другой аккаунт (бот при этом не создаётся).

Диалог с @BotFather построен на разборе его английских ответов. Если @BotFather изменит формулировки, бота
можно создать вручную и вписать токен в `aiogram_token`; включите ему `/setinline` и
`/setinlinefeedback` → `100%`.

**Что умеет бот сам:** `/start` (всем), `/status` (владельцу). Всё остальное добавляют модули
([раздел 28](#28-стационарный-бот-в-модулях-import-bot-inline_function-enginebot)).

**Безопасный HTML.** Бот — это `FRXBot`, подкласс `aiogram.Bot`: перед каждым запросом к Bot API HTML-поля
(текст, подпись, тексты инлайн-результатов) проходят `safe_html()` — «теги», которых Telegram не знает
(`<имя_модуля>`, `<chat_id>`), показываются как текст, а не ломают отправку ([раздел 34](#34-безопасный-html-safe_html)).

## 10. Мультиаккаунт

FRX может держать несколько аккаунтов Telegram и переключаться между ними на лету.

- **Первый аккаунт** — тот, под которым вы вошли при первом запуске; его сессия — файл
  `user/data/frx_session.session`.
- **Добавленные** через `.acc` (или на сайте) хранятся в `user/data/accounts.json` как `StringSession`
  под номером телефона, с тегами и сведениями профиля. Как только там появился хотя бы один аккаунт, при
  запуске поднимается **последний активный** из `accounts.json`.
- **Переключение** — `.acc` → «Переключить аккаунт» или на сайте. Все команды, наблюдатели и формы сразу
  начинают работать на новом аккаунте; модули получают событие `@decorators.on_account_switch()`; бот
  присылает уведомление (Logging) и получает `/start` от нового аккаунта, если тот ещё не писал ему.
- **Удаление** — отключает клиент и удаляет запись (активный аккаунт удалить нельзя — сначала переключитесь).
- **Сведения профиля** (id, имя, username) обновляются после добавления аккаунта и кнопкой «обновить» на
  сайте; при этом замечается и смена номера телефона — запись переименовывается на новый номер (сессия
  привязана к аккаунту, а не к номеру).

API для модулей — [раздел 31](#31-accounts-мультиаккаунт-из-модулей).

## 11. Доступ для других людей и алиасы

### Как это работает

Вы можете разрешить другим людям пользоваться вашим юзерботом. Гость пишет команду с тем же префиксом
(`.help`, `.ping`, …) в чате, где его видит ваш аккаунт — в личке с вами или в общей группе, — и команда
выполняется так, будто её написали вы. Ответ приходит ответом на сообщение гостя, а последующие правки
ответа (например, «измеряю…» → результат) правят этот же ответ. Сообщения людей без доступа и команды,
которые гостю не выданы, молча игнорируются — никакого ответа «нет доступа» нет, гость не узнаёт, какие команды
у вас есть.

**Доступ складывается только из выдач — запретов нет.** Выдать можно:

- **класс** — готовый набор выдач с именем; у человека может быть один класс;
- **разрешение** — один модуль целиком или одна команда модуля;
- **набор модулей** — «все модули», «все встроенные», «все загруженные» (ваши модули из `user/modules/`).

Команда разрешена, если её покрывает хоть одна выдача — личная или из класса. Исключение одно: управление
доступом и алиасами (модули Access и Aliases) — всегда только у владельца.

**Класс** описывается тремя полями: **idn** — ID класса, одно слово (буквы, цифры, `_`, без пробелов), например
`helpers`; **название** — произвольное; **описание** — что класс разрешает и кому его выдавать. Готовые классы:
`FULL` — все модули (системный: его выдачи не меняются, удалить нельзя) и `LOADED` — все загруженные модули.
Свои классы создаются и настраиваются на сайте.

**Критически опасные модули.** Выдавать можно что угодно, но часть модулей помечена ⚠ как критически опасные:
доступ к ним фактически равен доступу ко всему аккаунту и компьютеру, где запущен юзербот. Встроенные:
`eval` (любой код), `loader` (загрузка модулей), `systemkeeper` (обновление и перезапуск), `backup` (бэкапы с
сессиями), `account_manager` (аккаунты и сессии), `neurodash` (нейро-агент с файлами и кодом), `web_panel`
(ссылка входа на сайт), `config` (настройки всех модулей). Загруженные модули помечаются по их коду: если модуль
выполняет код (`exec`/`eval`), загружает модули, запускает программы, читает или меняет файлы, скачивает файлы,
работает с аккаунтами и сессиями. Перед выдачей опасного Telegram и сайт переспрашивают.

**Что ещё проверяется для гостей.** Действия над самим юзерботом — загрузка, выгрузка и перезагрузка модулей,
переключение аккаунта, остановка и перезапуск, смена префикса — выполняются по команде гостя, только если их
вызывает код модуля-хозяина действия (`loader`, `account_manager`, `systemkeeper`/`backup`, `config`), чья
команда гостю выдана, или если гостю выдан такой модуль целиком. Так выданная гостю `.dlm` работает, а чужой
модуль не загрузит код «от имени» гостя. Запуск команды другого модуля из кнопки (`engine.exec_modcmd`) тоже
проверяет выдачи гостя.

**Инлайн-формы.** Форма, которую создала команда гостя, доступна для нажатия и владельцу, и этому гостю.

> Класс `FULL`, «все модули» и любые критически опасные модули — это **полный контроль** над вашим аккаунтом.
> Выдавайте их только тем, кому доверяете как себе.

### Управление в Telegram — `.access`

Главный способ — **ответить командой `.access` на сообщение человека.** Откроется меню этого человека:

- сверху — какой доступ у него сейчас: класс (с описанием и тем, что он даёт), личные разрешения (опасные — с ⚠)
  и сколько команд ему доступно;
- **«Выдать доступ»** → **«Выдать класс»** (список классов → карточка класса с тем, что он даёт, и
  предупреждением, если там опасное → «Выдать класс …») или **«Выдать разрешение»** (список модулей, опасные
  с ⚠ → модуль: кнопка «Выдать доступ ко всему модулю», а ниже его команды → команда: «Выдать доступ к .команда» —
  тогда доступ будет только к этой команде). Для опасных модулей перед выдачей — отдельное подтверждение.
- **«Отозвать доступ»** (если доступ есть) — класс и каждое разрешение отдельной кнопкой, нажатие отзывает;
  внизу «Отозвать весь доступ» с подтверждением.

| Команда | Что делает |
|---|---|
| `.access` ответом на сообщение | меню этого человека (см. выше) |
| `.access <id \| @username>` | то же меню без ответа |
| `.access` | список всех, у кого есть доступ (нажатие — меню человека), и просмотр классов |
| `.access grant [пользователь] <что>` | выдать текстом: класс (`LOADED`), модуль (`ping`), команду (`.dping` или `ping:dping`), набор (`all`, `builtin`, `loaded`) |
| `.access revoke [пользователь] [что \| class]` | отозвать одну выдачу или класс; без «что» — весь доступ |
| `.access check [пользователь] <команда>` | доступна ли команда и почему |
| `.access list`, `.access classes` | списки текстом |

Если `grant`/`revoke`/`check` отправлены ответом на сообщение, пользователя указывать не нужно. Текстовые
подкоманды работают и без стационарного бота. Ваш аккаунт должен хотя бы раз «видеть» человека (личка, общий
чат), чтобы выдать доступ по `@username` или id.

### Управление на сайте — вкладка «доступ»

- **У кого есть доступ:** список людей (класс, число разрешений, ⚠ если есть опасное). «Выдать доступ» —
  ввести `@username` или id и перейти на страницу человека.
- **Страница человека** — то же, что инлайн-меню, но удобнее: сколько команд доступно; «выдать класс» (окно со
  списком классов → карточка класса с тем, что он даёт, и предупреждениями → «выдать класс»); «+ выдать
  разрешение» (окно выбора, см. ниже); блок «класс» с кнопкой «снять класс»; «личные разрешения» — каждое с
  «отозвать»; проверка команды («доступна ли и почему»); «отозвать весь доступ».
- **Классы:** «новый класс» — idn, название, описание (и можно начать с копии другого класса). Страница класса —
  те же три поля (idn можно переименовать, люди с классом переедут на новый idn), «что даёт класс» со списком
  выдач и кнопкой «отозвать» у каждой, **«+ добавить доступ»** и список людей с этим классом; «удалить класс»
  (люди остаются без класса).
- **Окно выбора доступа** (и для класса, и для человека): поиск по модулям и командам; наборы модулей («все
  модули», «все встроенные», «все загруженные»); модули с описанием и пометкой «⚠ критически опасно» —
  «+ весь модуль» или раскрыть и выдать одну команду («+ выдать»). Уже выданное помечено «выдано ✓». Для
  опасного — подтверждение с причинами. Окно не закрывается после выдачи — можно выдать несколько подряд.

### Алиасы

Алиас — своё короткое имя для любой команды, сразу с аргументами. Пишется `.alias <команда> [аргументы]
<новое_имя>`: первое слово — команда, последнее — новое имя, всё между ними — аргументы.

```
.alias help h2              .h2          → .help
.alias config helper cs     .cs          → .config helper
                            .cs extra    → .config helper extra
.alias                      список алиасов
.unalias cs                 удалить
```

- Имя алиаса — одно слово; оно не может совпадать с существующей командой (команды всегда главнее). Целевая
  команда должна существовать; если её модуль потом выгрузят, алиас просто перестанет срабатывать (в списке
  будет пометка).
- Всё, что дописано после алиаса, добавляется в конец его аргументов.
- Алиасами могут пользоваться и гости — права проверяются по целевой команде.
- **На сайте** алиасы — внизу вкладки «конфиги»: список с «изменить» и «удалить» и «+ новый алиас» — пошаговое
  окно: модуль → команда (со списком и описаниями) → аргументы и имя, с живым предпросмотром
  `.имя → .команда аргументы`.
- Хранятся в БД (`core:aliases`), управляются только владельцем.

## 12. Локальный сайт .web

### Запуск и доступ

`.web` (`.site`) поднимает сайт управления (`core/web/`) и присылает ссылки — в чат, где написана команда, и в
ЛС от стационарного бота (там же кнопки «Открыть в Telegram» и «Открыть в браузере»). Сайт **не работает
постоянно**: по умолчанию он выключается сам после 5 минут без активности (настройки `autostop`,
`autostop_minutes` модуля Web), `.web stop` выключает сразу, `autostart` поднимает его при запуске юзербота.
Пока сайт выключен, keeper держит его порт «сторожем» (`web_sentinel` в `user/config.json`): достаточно открыть
адрес — сайт поднимется сам, страница обновится. При `.restart`/`.update` сайт не пропадает: на время
перезапуска появляется плашка «юзербот спит», нажатия подсвечиваются красным, а когда юзербот проснулся,
страница обновляется сама.

**Три способа открыть сайт:**

| Откуда | Как | Адрес |
|---|---|---|
| с той же машины | просто открыть | `http://127.0.0.1:8878` |
| с другого компьютера по SSH | `ssh -L 8878:127.0.0.1:8878 пользователь@сервер`, окно не закрывать | `http://127.0.0.1:8878` у себя |
| откуда угодно, с телефона, прямо в Telegram | `.web tunnel on` | `https://<слова>.trycloudflare.com` |

Порт — из ответа на `.web` (настраивается `web_port`). SSH-клиент есть в Linux, macOS и Windows 10+
(PowerShell); установщик в конце печатает готовую команду с IP сервера.

**Публичный адрес (туннель).** `.web tunnel on` (или настройка `tunnel`) — keeper поднимает «быстрый туннель»
Cloudflare: программа `cloudflared` соединяется с Cloudflare и получает случайный адрес
`https://….trycloudflare.com`, который ведёт на порт сайта. Не нужны ни домен, ни аккаунт Cloudflare, ни
открытые порты и «белый» IP — работает и за NAT, и на домашнем компьютере. `cloudflared` берётся из `PATH`,
иначе сам скачивается в `user/data/bin/` (официальные сборки для Linux x86/ARM, macOS, Windows). Туннель живёт
в keeper'е, поэтому адрес не меняется при `.restart`/`.update`, а через него работает и «юзербот спит», и
сторож, поднимающий выключенный сайт. Адрес меняется при перезапуске keeper'а и по `.web tunnel new` (если
адрес попал не в те руки) — новая ссылка (и код входа) сразу приходит в ЛС от бота, старая перестаёт работать.

Как keeper следит за туннелем: адрес считается рабочим только после того, как `cloudflared` подключился к
Cloudflare (до этого Cloudflare отвечает ошибкой **1033**); соединение идёт по TCP (`--protocol http2`), потому что
на многих серверах закрыт UDP. Раз в минуту keeper сам открывает адрес: три ответа «1033» подряд — `cloudflared`
перезапускается за новым адресом (не чаще 3 раз в час), не подключился за 90 секунд — тоже. Ошибка 1033 в
браузере обычно значит, что ссылка старая (FRX перезапускали) — возьмите свежую: `.web` или `.web tunnel`. Если Cloudflare не выдаёт туннель (сеть, лимиты), keeper пробует запасной вариант —
`localhost.run` через обычный `ssh` (адрес `https://….lhr.life`). Состояние — `.web tunnel`, выключить —
`.web tunnel off`. Свой домен за reverse-proxy с HTTPS тоже можно — впишите его в `web_hosts` (`user/config.json`).

**Вход.** Сайт открывает только владелец юзербота — и локально, и по публичному адресу:

- **Код из Telegram — вход «закрыт» по умолчанию.** Страница входа без вашей команды показывает только «вход
  закрыт»: код запросить нельзя, подбирать нечего. `.web` (или `.web login`) открывает вход на 10 минут для
  ОДНОГО устройства и присылает 5-значный код — в ЛС от бота вместе со ссылками (без бота — в «Избранное»).
  Открытая страница входа замечает это сама и показывает поле для кода. После успешного входа вход снова
  закрыт — второе устройство с тем же кодом не войдёт; после 5 неверных кодов он тоже закрывается, и владелец
  получает предупреждение. «прислать новый код» на странице работает, только пока вход открыт (раз в 30 с,
  до 3 раз).
- **Кнопка «Открыть в Telegram»** под сообщением бота открывает сайт как Telegram Mini App — без кода: Telegram
  подписывает данные запуска токеном бота, сервер проверяет подпись и что это владелец. Нужен публичный адрес.
  То же делает постоянная кнопка «Сайт» в меню чата с ботом — её адрес обновляется сам.

После входа устройство помнит его `session_days` дней (cookie `HttpOnly`; по публичному адресу — ещё и
`Secure`). «выйти» в шапке — выйти на этом устройстве, `.web logout` — на всех. Сессии хранятся в
`user/data/web_sessions.json` (только хеши) и переживают перезапуск.

**Остальная защита.** Заголовок `Host` должен быть из разрешённых (`127.0.0.1`/`localhost`/`[::1]`, адрес
туннеля, `web_hosts`) — защита от DNS-rebinding; каждый `/api`-запрос обязан нести заголовок `X-FRX` (браузер не
пошлёт его с чужой страницы), `Origin` — тоже из разрешённых; строгий CSP, встраивание во фрейм — только в
Telegram. Не открывайте порт сайта наружу напрямую (`0.0.0.0`, проброс порта) — для этого есть туннели. В Docker
сайт слушает `0.0.0.0` внутри контейнера (`FRX_WEB_BIND`), а наружу compose публикует его только на `127.0.0.1`.

Все данные модулей попадают в браузер только как текст и безопасные узлы — HTML модулей не исполняется.
Сайт работает без интернета и внешних библиотек: шрифт, стили и скрипты лежат в `core/web/static/`.
Оформление — тёмное с красно-оранжевыми акцентами; системная настройка «уменьшить движение»
(`prefers-reduced-motion`) отключает анимации.

**Режим «3d» (экспериментальный)** — по умолчанию включён на компьютере и выключен на телефоне; переключатель
`3d` в шапке (на телефоне — внизу меню), выбор запоминается в браузере. Хромированные заголовки со слэшем, огненной чертой и счётчиком раздела («03 / 08»), панели в перспективе
с огненными уголками и бегущим бликом, лёгкий наклон панелей за курсором, страницы прилетают из глубины, а окна
раскрываются в перспективе; на фоне — уходящая за горизонт сетка. Рабочие поверхности (WebIDE, Lab, BotChat,
Emulate, Sandbox) не наклоняются; на узких экранах наклона и сетки нет. Стили — `depth.css`, логика — `depth.js`.

### Разделы

Меню — горизонтальная полоса в шапке (листается стрелками, колесом и свайпом; «все» раскрывает пункты
в несколько рядов). **На телефоне** (экран до 760 px) вкладки уезжают в боковое меню: нажмите «frx ☰» — слева
выедет список разделов; выбрали раздел — меню закрылось и открылся раздел; «frx» вверху меню — на главную;
нажатие мимо меню (или Esc) — закрыть. Внизу меню — `3d`, «выйти» и «выключить сайт».

Остальное на телефоне устроено по правилу «один экран — одно дело»: то, что на компьютере стоит колонками рядом,
переключается сегментами сверху, а мелкие окна выезжают шторкой снизу (закрывается тапом мимо или свайпом вниз).

- **WebIDE Lab** — на экране только скрипт; палитра блоков — по круглой кнопке «+» (блок встаёт после выбранного).
  У каждого блока «⋯»: выше / ниже, вложить в блок выше, вынести наружу, дублировать, копировать / вставить,
  выключить, удалить. Удерживайте шапку блока ~полсекунды — и тащите его пальцем. «код · проверка · перем.» — сегментами.
- **Редактор кода** — на всю высоту; над клавиатурой полоска символов, которых нет на телефонной раскладке
  (Tab, скобки, `:` `"` `=` …, отмена / повтор, поиск). Конструкции, история и neuro — сегментами.
- **Sandbox** — на весь экран, «чат» и «журнал и данные» по очереди. **Emulate** — «команды» и «лента»; после
  «запустить» сразу открывается лента.
- **neuro** — категории инструментов свёрнуты, тап по шапке раскрывает.
- **README** — разделы выпадающим списком по кнопке с названием текущего раздела (там же поиск).
- **BotChat** — поле ввода во всю ширину; пока пишете, «+» и «тихо» встают строкой выше, «отправить» — стрелка справа.
- Модальные окна сайта открываются шторкой во всю ширину; кнопки в шапке страниц — под заголовком.

### Emulate — команды любого модуля на сайте

Emulate сам рисует любой модуль с командами — автору ничего писать не нужно.

| В модуле | Что на сайте |
|---|---|
| команда без аргументов | строка команды с кнопкой «запустить» |
| команда с аргументом (`engine.get_args()`, `event.raw_text`/`event.text`, `<арг>`/`[арг]` в первой строке докстринга) | поле ввода + «запустить» (Enter тоже запускает) |
| ответы `engine.answer/reply/noreply/send_message`, `event.reply/edit/respond` | сообщения в ленте; HTML Telegram превращается в безопасную разметку; `answer` после `answer` правит то же сообщение, как в Telegram |
| `engine.create_inlineform(...)` | текст и кнопки формы; клик → `form.on_click`, `form.edit` обновляет на месте, `form.close` гасит кнопки, `InputButton` → поле ввода → `form.on_input`. **Стационарный бот не нужен** |
| `engine.wait_message(...)` в чате команды | над лентой появляется поле «ответить» (работают `await`, `async for`, `cancel()`) |
| `click.answer("текст")` | всплывающее сообщение |
| `file=` в ответе | чип «⬇ имя · размер» для скачивания |
| исключение | красная строка в ленте + обычная обработка ошибок (`@on_error`, Logging) |

**Контекст команды** (блок над списком): ответ на сообщение (текст, автор — «я» или другой человек,
необязательный файл) — команда видит `event.is_reply`, `event.reply_to_msg_id`,
`await event.get_reply_message()` (с `raw_text`, `out`, `file`, `download_media()`), работает и
`files.download_reply_file(event)`; файл к самой команде — `event.file`, `event.photo`/`document`/… и
`event.message.download_media()`. Файлы лежат в `user/data/emulate_uploads/<модуль>/` и удаляются при выходе
(лимит — `emulate_upload_mb`, до 20 файлов за сессию). Рядом с командой — подсказки «нужен reply» /
«нужен файл» (по исходнику).

**Запросы к Telegram.** Ответы «в свой чат» Emulate перехватывает, но модуль может обратиться к Telegram
напрямую (`engine.client.*`, `engine.bot.raw.*`, другие чаты) — такие запросы идут на настоящий аккаунт.
Они видны в ленте: протокол (MTProto / Bot API), метод, краткое содержание (код, пароль и телефон скрыты),
длительность, итог и пометка «читает» / «меняет»; над лентой — счётчик.

Как устроено: команда вызывается с виртуальным событием `EmuEvent` (`chat_id` = ваше «Избранное», `out=True`,
`event.emulated = True`) внутри сессии `EmuSession`, которая кладётся в `ContextVar current_emulation`.
`answer/noreply/send_message`, `create_inlineform` и `wait_message` ядра проверяют этот ContextVar и, если
адресат — «свой» чат, отправляют результат на сайт. Вне сайта поведение ядра не меняется. Модуль может
узнать, что запущен с сайта: `getattr(event, 'emulated', False)`. Команды `exit`, `restart`, `update`,
`unloadmod`, `restorebackup` запускаются только после подтверждения; «остановить» отменяет выполняющиеся
команды и ожидания. Не эмулируются вотчеры и циклы (они работают сами по себе) и чтение чужих чатов.

### files

Три раздела и предпросмотр (картинки, видео, аудио, текст — первые 64 КБ), скачивание, загрузка (несколько
файлов, перетаскивание, прогресс; до 50 МБ), удаление:

- **файлы юзербота** — реестр `files` (`user/data/files`), каждый файл с id;
- **без записи в реестре** — файлы в `user/data/files`, о которых реестр не знает (можно добавить в реестр);
- **мои ассеты** (`user/assets/`, с подпапками) — свои файлы для `engine.asset_path()`, загрузка с выбором
  подпапки и заменой; **стоковые ассеты** (`assets/` проекта) — только просмотр и скачивание.

Сайт открывает только файлы внутри `user/data/`, `user/assets/` и `assets/` (пути проверяются через
`resolve()`, в том числе по symlink'ам); HTML/XML/JS/CSS отдаются как `text/plain` в песочнице CSP.

### Логи

`main.py` оборачивает stdout/stderr: каждая строка терминала получает метку `мм.дд чч:мм:сс` и попадает в
кольцевой буфер (3000 записей). Окно логов на главной фильтрует по источнику (юзербот / бот), уровню (инфо,
предупреждение, ошибка) и тексту, умеет паузу, «следить», копирование и очистку. Модулям ничего делать не
нужно: их `print` и `engine.tlog` попадают туда сами.

## 13. FRX WebIDE: редактор модулей

Вкладка **webide**: список «ваши модули» и «встроенные» (рядом с изменёнными в WebIDE — пометка и число
версий в истории), кнопка «создать».

| Что | Как устроено |
|---|---|
| Редактор | подсветка Python, номера строк, поиск и замена |
| Клавиши | `Ctrl+S` сохранить, `Ctrl+F` поиск, `Ctrl+H` замена, `F3`/`Shift+F3`, `Ctrl+G` к строке, `Ctrl+/` комментарий, `Tab`/`Shift+Tab` (и на выделении), `Alt+↑/↓` перенести строку, `Alt+Shift+↑/↓` дублировать; автозакрытие скобок и кавычек, умный `Enter` (отступ после `:`), Backspace в отступе стирает уровень |
| Встроенные модули | только просмотр |
| Защита шапки | у существующего модуля нельзя менять `NAME`, `MODULE_NAME`, `AUTHOR` (`VERSION` и `DESCRIPTION` — можно). Проверка — на сервере через `ast`, в браузере правки этих строк блокируются |
| Метка WebIDE | в `AUTHOR` дописывается «… \| изменён в FRX WebIDE» (у созданного в WebIDE — «создан в FRX WebIDE»); повторные сохранения не плодят дубли |
| Сохранение | выгрузка → загрузка нового исходника; если новая версия не загрузилась — прежняя возвращается автоматически |
| История | `user/data/webide/history/<MODULE_NAME>/` — 60 последних версий; снимок делается только после успешной загрузки |
| Черновики | несохранённые правки кода и проектов Lab уходят к юзерботу через ~1,5 с после правки (`user/data/webide/drafts/`). Открыли модуль — с любого адреса или устройства, после смены публичного адреса или перезагрузки — сайт предложит «восстановить» или «отбросить». После сохранения модуля черновик удаляется; старше 30 дней — тоже |
| Ошибки синтаксиса | тихо подсвечиваются после паузы в наборе; всплывающее сообщение — при сохранении и запуске |

**Конструкции** (кнопка справа) собирают код через форму с живым предпросмотром; код встаёт в место курсора
с правильными отступами, недостающие `import` добавляются сами, `Ctrl+Z` откатывает вставку целиком.

| Конструкция | Что собирает |
|---|---|
| Шапка модуля | `NAME`, `MODULE_NAME`, `VERSION`, `AUTHOR`, `DESCRIPTION`; если шапка есть — обновляет `VERSION` и `DESCRIPTION` |
| Декоратор | декоратор, функция и докстринг: `command`, `watcher`, `on_start`, `on_load` (с условием «только этот модуль»), `cycle`, `telegram_event`, `callback`, `on_error`, `on_account_switch`; для бота — `command`, `watcher`, `on_start`, `on_load`, `cycle`, `telegram_event`, `on_error` |
| Inline-форма | `form = await engine.create_inlineform(...)` с макетом клавиатуры как в Telegram (ряды, кнопки, `InputButton`) |
| Обработчик кнопки | `@form.on_click(data=...)` / `@form.on_input(...)`; знает кнопки форм из файла (у которых обработчик уже есть — серые) |
| form.edit | `await form.edit(...)` с текстом и кнопками выбранной формы; «оставить как есть» / «новые» / «убрать» |
| Конфиг | `await engine.create_config(...)` всех типов с `valid=` и `options=` |
| Данные | `db`/`cache`: прочитать, записать, увеличить, добавить в список, удалить (и `g*`-варианты) |
| Иконка | сетка иконок `visual` с поиском |
| Лог | `engine.tlog(...)` или `engine.botlog(..., level=...)` |

Окно показывает итоговое имя функции (`авто → hello_cmd`) и проверяет, что имя и команда не заняты в файле.
Код в предпросмотре можно править — правки разбираются обратно в поля. Если курсор стоит внутри
распознанной конструкции, у её первой строки появляется кнопка `> править · <название>`: окно откроется с
полями из кода, «заменить в коде» перезапишет блок (у декоратора — только шапку, тело функции не трогается).

**Помощник-нейросеть** (вкладка neuro справа от редактора) — три режима: «изменить выделенное», «вставить в
курсор», «спросить» (вопрос по коду с историей беседы). Ответ идёт потоком; для правок показываются отличия
и кнопки «подтвердить изменения» / «отклонить», `Ctrl+Z` откатывает применённое. Правку, задевающую
защищённые строки шапки, применить нельзя. Модель для помощника выбирается отдельно от NeuroDash. Код
уходит выбранному провайдеру — для приватного кода выбирайте локальную модель (Ollama).

## 14. FRX WebIDE Sandbox: песочница модулей

Панель под редактором (кнопка **sandbox**, `Ctrl+Enter`). Проверяется то, что сейчас в редакторе, а не файл
на диске.

**Изоляция.** Модуль исполняется в своём потоке со своим event loop; `import engine/bot/db/cache/visual/
waiters/files/time_utils/time/datetime/asyncio` внутри него возвращают объекты песочницы. Настоящий
Telegram, `database.json`, настройки и часы ядра не затрагиваются. **Не изолированы** (обычный Python):
файловая система, сеть, сторонние библиотеки. Клиент Telethon, aiogram и стационарный бот заменены
заглушками с типовыми методами (отправка, правка, удаление, пересылка, закрепление, `get_entity`,
`iter_messages`, формы); остальное даёт понятную ошибку «не эмулируется в Sandbox».

| Что | Как устроено |
|---|---|
| Чаты | «Избранное», ЛС (с юзерботом и с ботом отдельно), группа, канал; свои участники и чаты (сохраняются в `user/data/sandbox/people.json`, общие для всех модулей). У чата сторона: юзербот / бот / оба |
| Сообщения | от любого участника в любой чат, ответ на сообщение, вложение (виртуальное или настоящий файл до 1 МБ). Команда срабатывает только от владельца с префиксом; вотчеры видят всё |
| События | служебное событие Telegram, статус участника, callback-кнопка, `on_error`, `on_load` другого модуля, смена аккаунта, `on_start` |
| Формы | рисуются как в Telegram; клик от имени выбранного участника с проверкой `for_user`/`black_list`, `InputButton` |
| db / cache | журнал каждого обращения, таблица ключей (чтения, записи, промахи, функция), правка и импорт |
| Время | виртуальные часы: сдвиг, установка момента, ход ×1…×3600 — по ним идут `time`, `datetime`, `asyncio.sleep`, `@cycle`, `wait_message`, таймауты форм |
| Журнал | события, вызовы с длительностью, ошибки (клик — переход к строке в редакторе), db/cache, отправка, конфиги, время; фильтры и поиск |
| Перезапуск | «↻ перезапуск» — как перезапуск юзербота: cache очищается, db возвращается к записанному, модуль загружается заново |
| Защита | обработчик не отдаёт управление ~5 с (цикл без `await`) — поток останавливается с сообщением |

`time.sleep()` в песочнице не блокирует, а сдвигает виртуальное время (с предупреждением). Цепочка «модуль
отвечает на свои же сообщения» обрывается на глубине 8. `engine.get_module_list()` возвращает настоящие
имена модулей плюс тестируемый. Не эмулируются `bot.inline_function`, MTProto-запросы `client(Request)` и
модуль `accounts`.

## 15. FRX WebIDE Lab: конструктор модулей

Вкладка `#/lab` (кнопка «FRX WebIDE Lab» на странице webide) — модуль из блоков, без программирования.
Готовый Python сохраняется тем же путём, что и из редактора (те же проверки, метка, история).

- **Проект** — название, `MODULE_NAME`, версия, описание, настройки (включая `choice`/`choices`) и скрипты.
  Скрипт = шапка (тип запуска: команда, вотчер, цикл, старт и т. д.) и список блоков; у блоков-контейнеров
  есть вложенные слоты.
- **14 категорий блоков**: сообщения, событие, переменные, списки и словари, математика, текст, управление,
  время, хранилище, формы, ожидание, файлы, чаты и люди, отладка.
- **Значения**: число, `{переменная}`, текст с подстановками `{имя}` и встроенными `{@текст}`, `{@аргументы}`,
  `{@чат_id}`, `{@отправитель_id}`, `{@кнопка}`, `{@кликнул_имя}`, `{@введено}`, `{@ошибка}`, `{@время}` и др.
  (доступность зависит от скрипта); в сообщениях значения экранируются.
- **Цепочки**: «Если» → «Иначе, если» → «Иначе», «Попробовать» → «Если ошибка» — порядок проверяется.
- **Формы**: «Создать форму» (макет клавиатуры) + «Нажали кнопку» / «Ввели значение» с выбором кнопки.
  «Изменить форму» правит кнопки, «убрать кнопки» их убирает.
- **Ожидание**: «Спросить и дождаться» / «Дождаться сообщения» пропускают собственные сообщения скрипта.
- **Сохранение**: файл модуля + проект в конце файла (base64 в комментариях). `AUTHOR` получает метку
  «FRX WebIDE Lab». Ручные правки кода Lab замечает и предупреждает: синхронизация только «проект → код».
- **Запуск в Sandbox** (`Ctrl+Enter`); строка ошибки в журнале выделяет блок.
- Клавиши: `Ctrl+S`, `Ctrl+Enter`, `Ctrl+Z`/`Ctrl+Y`, `Ctrl+D` дублировать, `Ctrl+C`/`Ctrl+V` блоки,
  `Delete`, `Alt+↑/↓`; блоки перетаскиваются с палитры и между скриптами.
- Нет блоков для `bot.inline_function`, страниц сайта и MTProto-запросов.

## 16. BotChat: аккаунт стационарного бота на сайте

Вкладка `#/botchat` — переписка от имени бота «как в Telegram». Нужен запущенный стационарный бот.

**Как копится история.** Bot API не отдаёт ни список чатов, ни историю, поэтому BotChat ведёт локальное
хранилище `user/data/botchat/store.json` (файлы — `media/`, аватарки — `avatars/`):
входящие апдейты (сообщения, правки, посты каналов, реакции, опросы, статус бота в чатах) и результаты
каждого вызова Bot API (то, что отправили `engine.bot.*`, формы, хэндлеры и сам сайт) попадают в историю.
Хэндлеры модулей это не затрагивает. История — с момента, как BotChat увидел сообщение; глубина —
`history_limit` на чат.

**Интерфейс.** Список чатов (аватарки, превью, непрочитанные, поиск, закрепление, «новый чат» по
`@username`, ссылке `t.me` или id); лента с днями, цитатами, пересылками, форматированием, фото, видео,
GIF, кружками, стикерами, аудио, голосовыми, документами, геопозициями, контактами, кубиками (с анимацией),
опросами, альбомами, реакциями и инлайн-кнопками (URL-кнопки работают, callback — неактивны), подгрузка
старой истории, лайтбокс. Композер: мини-markdown (`**жирный**`, `__курсив__`, `~~зачёркнутый~~`,
`||спойлер||`, `` `код` ``, блоки кода, `[текст](url)`, `> цитата`; `Ctrl+B/I/E`, `Ctrl+Shift+X/P`),
вложения (кнопка «+», перетаскивание, вставка) с выбором типа (фото, файлом, GIF, аудио, голосовое, кружок),
спойлер, «тихо», ответ (двойной клик), правка (↑ в пустом поле), черновики; запись голосовых (до 10 мин) и
кружков (до 60 с) с превью; прогресс отправки и отмена. Меню сообщения: реакции, ответить, копировать,
править, переслать (или скопировать без заголовка), закрепить, ссылка, выбрать, удалить или убрать только из
истории сайта. Панель «инфо»: описание, участники, админы, участник по id (выгнать, забанить, разбанить),
название и описание (если бот админ), очистка истории, покинуть чат. **Профиль бота**: имя, описания,
список команд, аватарка.

**Группы, где бот не видит сообщения** (не админ и privacy mode): над лентой плашка и переключатель
**cross watch** — сообщения группы копируются в историю глазами вашего аккаунта (файлы скачивает юзербот,
до 50 МБ). Группа, ставшая супергруппой, склеивается в один чат.

**Кружки, голосовые, GIF** конвертируются ffmpeg (`core/media_tools.py`: из `PATH` или пакета
`imageio-ffmpeg`): кружок — квадрат 384×384 до 60 с, голосовое — ogg/opus, GIF → MP4. Без ffmpeg кружок не
отправляется, голосовое уходит аудиофайлом.

**Ограничения Bot API (обойти нельзя):** бот не видит чаты, где его не было; не нажимает инлайн-кнопки; не
видит «печатает», онлайн и прочтение; скачивает файлы до 20 МБ и отправляет до 50 МБ; не может первым
написать человеку, который не писал боту; сообщения старше 48 часов Telegram может не дать удалить.

Из модулей: `engine.botchat` (`chat_list()`, `page()`, `search()`, `message()`, `stats()`, `clear()`).

## 17. Нейросети: NeuroDash, подключения, инструменты

### Подключения и модели (сайт → neuro)

Подключение = провайдер + ключ (+ адрес для своих серверов). Провайдер выбирается вручную — ключ уходит
только ему.

| Провайдер | Протокол | Заметки |
|---|---|---|
| Ollama | `/api/tags`, `/api/chat` | локально, ключ не нужен; добавляется сам, модели сканируются при открытии вкладки |
| OpenAI, DeepSeek, OpenRouter, Groq, xAI, Google Gemini, Mistral | OpenAI-совместимый `/chat/completions` | Gemini — через `…/v1beta/openai` |
| Свой адрес | OpenAI-совместимый | LM Studio, vLLM, llama.cpp, прокси; ключ необязателен |
| Anthropic (Claude) | `/messages` | |
| GigaChat (Сбер) | OAuth по «ключу авторизации» + чат | вставляется бессрочный Authorization key; временный токен FRX получает и обновляет сам; область PERS/B2B/CORP; `verify_ssl` для сертификатов Минцифры |

После добавления сразу запрашивается список моделей; если провайдер отверг ключ (401/403), подключение не
сохраняется. Модели для эмбеддингов, распознавания речи, синтеза и картинок в список чата не попадают.
Модели можно включать и выключать; модель выбирается отдельно для NeuroDash и для помощника WebIDE.

**Ключи** хранятся в `user/data/neuro/providers.json` открытым текстом (иначе ими нельзя пользоваться;
права файла 600, где ОС это умеет). На сайте показываются маской, целиком — по кнопке «показать». В логи,
тексты ошибок и файл расхода ключи не попадают.

**Расход и лимиты.** `user/data/neuro/usage.json`: счётчик на подключение (вход, выход, запросы) и история
по дням и моделям (график за 30 дней на сайте). Токены берутся из ответа провайдера, иначе — оценка (`~`).
**План** подключения: лимит токенов, период (`без периода`, `день`, `неделя`, `месяц`, `всего`) и «жёсткий»
режим — превышение блокирует запросы. Для DeepSeek и OpenRouter показывается баланс провайдера.

### NeuroDash в Telegram — `.neuro`

`.neuro` / `.n` — инлайн-чат (нужен стационарный бот): кнопки «Написать…», «Модель» (провайдер → модель),
«Сбросить контекст». Ответ идёт потоком. Над каждым блоком — строка расхода: `context (N) ↑вход ↓выход`,
расход за обращение, всего по подключению и остаток плана. Если история не помещается в сообщение,
скрываются самые старые блоки (в контексте модели они остаются). Опасный инструмент показывает, что хочет
запустить, и ждёт кнопок «Разрешить» / «Отклонить» (90 секунд); «тяжёлый» — предупреждает о токенах.

### Инструменты

Инструмент — файл `user/data/neuro/tools/<категория>/<имя>.py` с заголовком в докстринге и функцией `run`:

```python
"""
name: shout
category: fun
title: Крик
description: возвращает текст ЗАГЛАВНЫМИ
args: text: string
example: {"text": "привет"}
dangerous: false
keywords: крикни, громко
"""
async def run(text: str = '') -> str:
    return text.upper() + '!'
```

| Поле заголовка | Обязательно | Смысл |
|---|---|---|
| `name` | да | имя: латиница в нижнем регистре, цифры, `_` (2–32 символа); совпадает с именем файла |
| `category` | да | категория (2–24 символа); совпадает с папкой |
| `description` | да | описание, которое видит модель |
| `title` | нет | название для людей |
| `args` | нет | аргументы для модели (`имя: тип`, `имя?: тип` — необязательный) |
| `example` | нет | пример аргументов в JSON |
| `dangerous` | нет | `true` — перед запуском подтверждение (`allow_dangerous`) |
| `heavy` | нет | пояснение «тяжёлого» инструмента (много токенов) — подтверждение (`allow_heavy`) |
| `keywords` | нет | слова, по которым открывается категория |
| `limit` | нет | свой предел длины вывода |

Код инструмента выполняется в процессе юзербота с правами модуля: доступны `import engine, db, cache, files`
(данные — от имени модуля `neurodash`). Аргументы проверяются по сигнатуре `run`, вывод обрезается до
`tool_output_limit`, время — до `tool_timeout`. Файл — не больше 40 КБ.

**Встроенный набор — 45 инструментов** (`core/neuro_seed/`, раскладываются в `user/data/neuro/tools/`;
нетронутые файлы обновляются сами, удалённые вами не возвращаются):

| Категория | Инструменты |
|---|---|
| math | `calculator`, `convert_units`, `statistics` |
| time | `get_current_time`, `date_calc` |
| files | `list_files`, `read_file`, `write_file`, `delete_file`⚠ — песочница `user/data/ai_files` |
| memory | `remember`, `recall`, `forget`, `add_task`, `list_tasks`, `complete_task` |
| web | `web_search` (DuckDuckGo → Bing → DuckDuckGo Lite → Википедия, без ключа), `fetch_url`, `http_json`, `wikipedia`, `news`, `weather`, `exchange_rate`, `crypto_price`, `translate`, `github_repo` |
| telegram | `list_chats`, `read_chat`, `search_messages`, `user_info`, `send_to_saved`, `send_message`⚠ |
| system | `frx_help`, `frx_readme` (тяжёлый), `list_modules`, `get_config_value`, `system_info`, `run_python`⚠, `run_command`⚠ |

⚠ — опасные (требуют подтверждения). `run_command` отправляет команду FRX от вашего имени в текущий чат;
`exit`, `restart`, `update`, `unloadmod`, `restorebackup`, `eval`/`exec`, сама нейросеть и SystemKeeper ей
запрещены. `frx_help` ищет по путеводителю `core/frx_guide.md`, затем по README и CHANGELOG.

**Экономия токенов.** В режиме `categories` (по умолчанию) в запрос идут описания только тех категорий,
которые подходят к вопросу по ключевым словам или которые модель открыла сама вызовом `open_category`;

## 18. Как устроено ядро

Дальше — для авторов модулей и тех, кто правит само ядро.

### Нет «магических» имён — только import

Код модуля исполняется в почти пустом пространстве имён (только `__name__` и `__builtins__`). Всё, чем
пользуется модуль, он **явно импортирует** — движок при старте кладёт нужные объекты прямо в `sys.modules`
(`Core._register_module_imports()`), поэтому никакие пакеты устанавливать не нужно:

```python
import engine        # сам объект Core: answer/reply/get_args/create_config/create_inlineform/tlog/client/...
import decorators    # command/watcher/on_start/on_load/cycle/telegram_event/callback/on_error/on_account_switch
import bot           # те же декораторы, но для стационарного бота + inline_function
import db            # постоянное хранилище модуля (JSON)
import cache         # то же, но в памяти до перезапуска
import waiters       # wait_message() — дождаться сообщения
import files         # реестр файлов
import accounts      # мультиаккаунт
import visual        # иконки и помощники оформления
import time_utils    # время
import web           # страницы сайта (@web.page)
```

Импортируйте только то, что используете. Кроме этих объектов, модуль может импортировать что угодно:
стандартную библиотеку, сторонние пакеты (поставленные `pip install` в то же окружение), внутренности ядра
(`from core.inline_forms import InlineClick`, `from core.paths import DATA_DIR`).

### Что происходит при запуске

1. `frx_systemkeeper.py`: переезд старой раскладки в `user/` (если нужно), откат прерванной замены файлов
   (если есть `journal.json`), запуск `python -u main.py` с `FRX_KEEPER=1`.
2. `main.py` читает `user/config.json` (спрашивает `api_id`/`api_hash` при первом запуске) и создаёт
   `Core(config)`. В конструкторе создаются БД, кэш, реестр файлов, нейросети (`engine.llm`, `engine.neuro`),
   менеджер аккаунтов, сайт (`engine.web`), BotChat, фасад бота (`engine.bot`, пока без бота), и
   регистрируются `import engine/decorators/bot/db/...`.
3. `await core.start()`:
   1. поднимается последний активный аккаунт из `accounts.json` или основной клиент
      `user/data/frx_session` (при необходимости — вход в консоли); запоминается id владельца;
   2. на клиент вешаются обработчики `NewMessage`, `ChatAction`, `CallbackQuery`;
   3. грузятся **встроенные** модули `modules/builtin/*.py` в алфавитном порядке (файлы на `_` пропускаются;
      ошибка одного файла не мешает остальным);
   4. грузятся **все** `*.py` из `user/modules/` (подпапка `unloaded/` не сканируется). Папка — единственный
      источник правды: что лежит, то и грузится. Индекс `core:loaded_modules` в БД тут же приводится к
      реальности. Файл, чей `MODULE_NAME` уже занят встроенным модулем, переименовывается в `*.py.bak`;
   5. у всех модулей вызываются `@on_start()` (в порядке загрузки);
   6. из БД удаляются настройки, которые модули больше не объявляют через `create_config()`.
4. `main.py` запускает приём сообщений, монитор сети и — если есть `aiogram_token` — стационарного бота
   (`aiobot.bot.create_bot()` вызывает `core.set_bot()`; только с этого момента работают `engine.bot.*` и
   формы, и вызываются все `@bot.on_start()`/`@bot.cycle()`). Токен, который Startup записал в
   `engine.config` во время `on_start`, подхватывается здесь же — это тот же словарь.
5. `main.py` пишет `ready.json` и работает, пока не завершатся задачи или модуль не попросит остановку
   (`engine.request_shutdown(code)`). Остановка корректная: сайт, бот, все клиенты Telethon, HTTP-сессия
   нейросетей.

> Порядок важен: `@decorators.on_start()` вызывается **до** подключения стационарного бота. Всё, что шлёт
> сообщения ботом при запуске, вешайте на `@bot.on_start()`.

### Диспетчеризация событий

**Новое сообщение** (`Core._on_new_message`, любое сообщение в любом чате):

1. Служебные сообщения «via ваш бот» (эхо ввода `InputButton`, вызовы `bot.inline_function`) разбираются
   отдельно и дальше не идут.
2. **Команда** — только если сообщение **исходящее** (`event.out`) и начинается с префикса: первое слово
   после префикса (без учёта регистра) ищется среди команд. Нет такой — тихо ничего не происходит.
3. **Вотчеры** (`@decorators.watcher()`) получают **все** сообщения — входящие, исходящие и команды.
4. `@bot.watcher(watch='userbot'|'all')` из модулей — отдельный поток с теми же событиями.

**Служебные события** (`ChatAction`: вход/выход участника, смена названия и фото, закреп) → все
`@decorators.telegram_event()`. **Клик по кнопке обычного сообщения** юзербота (`CallbackQuery` Telethon) →
все `@decorators.callback()`. Клики по инлайн-формам идут другим путём — через бота
([раздел 27](#27-инлайн-формы)). **Циклы** (`@decorators.cycle`) — отдельная задача на каждую функцию.

Каждый хэндлер вызывается через `Core._safe_call()`: исключение не роняет диспетчер, а уходит в
`@on_error` ([раздел 33](#33-ошибки-и-логи-on_error-tlog-botlog)).

### Контекст: текущий модуль и событие

`core/context.py` — три `ContextVar`: `current_module`, `current_event`, `current_emulation`. Движок
выставляет их на время каждого вызова хэндлера и возвращает обратно в `finally`. Поэтому `db.get()`,
`engine.get_args()`, `engine.create_config()` сами знают, какой модуль и какое событие сейчас
обрабатываются, — и это безопасно при параллельной обработке разных сообщений: каждая задача видит своё
значение.

Следствие: функции, зависящие от контекста, работают **внутри хэндлеров**. В задаче, запущенной вручную
через `asyncio.create_task()` из хэндлера, контекст копируется; в коде на верхнем уровне файла модуля его
нет (там `current_module = '__loading__'`).

## 19. Формат файла модуля

Модуль — один `.py`-файл (не пакет), который целиком исполняется при загрузке. Обязательные метаданные на
верхнем уровне:

```python
NAME = "Отображаемое имя"        # для людей; может повторяться у разных модулей
MODULE_NAME = "unique_name"      # технический ID, уникальный во всём юзерботе (латиница, цифры, _ и -)
VERSION = "1.0"                  # строка; другая версия при .loadmod = обновление
AUTHOR = "Ваше имя"
DESCRIPTION = "Что делает модуль"
```

Без `MODULE_NAME` модуль не загрузится. `MODULE_NAME` — единственный идентификатор модуля в движке: по нему
хранятся данные `db`, настройки, формы. Пользователь может обращаться к модулю и по `NAME` (`.help`,
`.config`, `.unloadmod` принимают оба).

**Докстринг хэндлера — его описание** для `.help` и сайта. Пишите только суть, без имени команды — префикс
и имя `.help` добавит сам. Аргументы упоминайте в угловых или квадратных скобках: по `<...>`/`[...]` в первой
строке Emulate рисует поле ввода.

```python
@decorators.command('remind', 'напомни')
async def remind_cmd(event):
    """поставить напоминание: <минуты> <текст>"""
```

Минимальный модуль:

```python
import engine
import decorators
import visual

NAME = "Привет"
MODULE_NAME = "hello"
VERSION = "1.0"
AUTHOR = "Вы"
DESCRIPTION = "Здоровается"


@decorators.command('hello', 'привет')
async def hello_cmd(event):
    """поздороваться: [имя]"""
    name = engine.get_args() or 'мир'
    await engine.answer(event, visual.ok(f"Привет, {engine.safe_html(name)}!"))
```

**Как установить:** отправьте файл себе (например, в «Избранное») и ответьте на него `.loadmod`; или
положите в `user/modules/` и перезапустите (`.restart`); или создайте прямо на сайте в WebIDE.

## 20. Загрузка и жизненный цикл модуля

### Как модуль загружается (`Core._load_from_source`)

1. Пустое пространство имён; на время исполнения `current_module = '__loading__'` — поэтому `db.*` и
   `engine.create_config()` **на верхнем уровне файла не работают**, используйте `@on_load`/`@on_start`.
2. `exec()` всего файла: импорты, определения функций, декораторы (они лишь помечают функции атрибутами).
3. Читаются метаданные. Модуль с таким `MODULE_NAME` уже загружен: та же версия — `ValueError`; другая —
   старая версия тихо выгружается (обновление).
4. Для пользовательского модуля исходник записывается в `user/modules/<MODULE_NAME>.py` (встроенные не
   перезаписываются).
5. Пространство имён сканируется на помеченные функции, они регистрируются в реестрах (команды, вотчеры,
   события, ошибки, хэндлеры бота, страницы сайта). Одна функция под двумя именами регистрируется один раз.
   Алиас команды занят другим модулем — `ValueError`, и **весь модуль не загружается**.
6. Модуль считается загруженным; запускаются его `@cycle`.
7. Вызываются `@on_load()` **всех** модулей (включая этот) с `ModuleInfo` загружаемого модуля.
8. Если юзербот уже работает (загрузка на лету) — сразу вызываются `@on_start()` этого модуля, а если бот
   подключён — и `@bot.on_start()`/`@bot.cycle()`.
9. Модуль заносится в индекс загруженных, его устаревшая копия в `unloaded/` удаляется.

Синтаксическая ошибка или исключение на верхнем уровне файла — модуль не загружается; при старте в
терминале `Ошибка загрузки модуля из <файл>: …`, остальные модули грузятся как обычно.

### load / unload / kill / reload

| Метод | Что делает | Файл |
|---|---|---|
| `await engine.load_module(path_or_reply, target='loaded')` | загрузить модуль из файла или из ответа на сообщение с файлом | создаётся в `user/modules/` |
| `await engine.unload_module(name, archive=True)` | снять все хэндлеры, циклы, страницы, формы и сессию Emulate модуля | `archive=True` — переносится в `user/modules/unloaded/`; `False` — не трогается; встроенные не архивируются |
| `await engine.kill_module(name)` | выгрузить и загрузить **тот же код из памяти** — сброс зависшего состояния | не трогается |
| `await engine.reload_module(name)` | выгрузить и загрузить **заново с диска** — применить ручные правки | перечитывается |

При выгрузке закрываются все активные инлайн-формы модуля, отменяются его циклы, сбрасывается состояние
его страниц сайта. Кнопка «Удалить модуль» в `.help` делает `unload_module(archive=False)` и удаляет файл.

### Выгруженные модули

```python
engine.list_unloaded_modules()        # СИНХРОННО -> [{'file','path','module_name','name','version','author',
                                      #   'description','commands','broken','loaded'}, ...] по алфавиту
engine.find_unloaded_module(query)    # по имени файла (с .py или без), MODULE_NAME или NAME -> dict | None
await engine.restore_module(query)    # вернуть в user/modules/ и загрузить -> ModuleInfo
await engine.delete_unloaded_module(query)   # удалить файл из unloaded/ навсегда -> True
engine.parse_module_meta(source)      # разбор исходника без исполнения -> dict | None
```

Разбор `unloaded/` — статический (`core/module_meta.py`), код не исполняется. `broken=True` — файл не
разобрался (его можно только удалить); `loaded=True` — модуль с таким `MODULE_NAME` сейчас загружен
(восстановить нельзя). `restore_module()` кладёт файл под прежним именем, при конфликте — под
`<MODULE_NAME>.py`, иначе `FileExistsError`; `KeyError` — не найден, `ValueError` — повреждён или уже
загружен.

### Информация о модулях

```python
engine.get_module_list()              # СИНХРОННО -> [MODULE_NAME, ...]
engine.get_module_info(name)          # СИНХРОННО -> dict (ниже)
engine.resolve_module(query)          # MODULE_NAME по точному MODULE_NAME или NAME (без регистра) -> str | None
engine.search_module(query)           # самый похожий MODULE_NAME (нечёткий поиск) -> str | None
engine.search_dec_module(query)       # модули с похожими командами -> list[str]
engine.modules[name]                  # ModuleInfo: .module_name .name .version .author .description .path
                                      #   .source .is_builtin .kind ('builtin' | 'loaded') .commands ...
```

`get_module_info()` возвращает: `module_name`, `name`, `version`, `author`, `description`, `is_builtin`,
`commands` (`[{'command', 'aliases', 'description'}]`), `watchers`, `telegram_events`, `callbacks`,
`on_start`, `on_load`, `on_error` (`[{'name', 'description'}]`), `cycles` (`+ 'interval'`), а также
`bot_commands`, `bot_inline_functions` (с `access`), `bot_watchers` (с `watch`, `access`),
`bot_telegram_events`, `bot_on_start`, `bot_on_load`, `bot_on_error`, `bot_cycles`.

### Запуск команды другого модуля

```python
ok = await engine.exec_modcmd(event, module, command, args='')
```

Запускает **команду** модуля так, как будто её ввёл пользователь: `engine.exec_modcmd(event, 'config',
'config', 'helper')` — это `.config helper`. `module` — `MODULE_NAME` или `NAME`; `command` — любой алиас
(с префиксом или без, без учёта регистра), не имя функции; `event` — настоящее событие (из вашей команды или
сохранённое в замыкании хэндлера кнопки). Внутри команды `engine.get_args()` вернёт `args`, `event.raw_text` —
`"<префикс><команда> <args>"`, остальное (`chat_id`, `edit`, `reply`, …) — от настоящего события
(`core/command_event.py`). Возврат: `True` — без исключений, `False` — команда упала (ошибка обработана как
обычно); `KeyError` — нет модуля или команды; `ValueError` — `event is None`. Права доступа не проверяются.

## 21. Декораторы юзербота

`import decorators`. Декоратор лишь помечает функцию; регистрация — при загрузке модуля.

| Декоратор | Когда срабатывает | Сигнатура |
|---|---|---|
| `@decorators.command('cmd', 'alias', ...)` | вы пишете `<префикс>cmd` или алиас (без учёта регистра) | `async def f(event)` |
| `@decorators.watcher()` | **любое** сообщение в любом чате, включая чужие и ваши команды | `async def f(event)` |
| `@decorators.on_start()` | один раз при запуске; при загрузке на лету — сразу | `async def f()` |
| `@decorators.on_load()` | загрузка **любого** модуля, включая этот | `async def f(module_info)` |
| `@decorators.cycle(interval='1m')` | каждые `interval`: `'30s'`, `'5m'`, `'2h'`, `'1d'` (первый вызов — через интервал после загрузки) | `async def f()` |
| `@decorators.telegram_event()` | служебные события Telegram (`ChatAction`) | `async def f(event)` |
| `@decorators.callback()` | клик по кнопке **обычного** сообщения юзербота (не формы) | `async def f(event)` |
| `@decorators.on_error()` | исключение в любом хэндлере любого модуля | `async def f(error_text, context)` |
| `@decorators.on_account_switch()` | после переключения аккаунта (`engine.client` уже новый; не при первом запуске) | `async def f(number)` |

- Алиасы команды приводятся к нижнему регистру; несколько `@command` на одной функции складываются.
- `event` — стандартное событие Telethon: `event.raw_text`, `event.chat_id`, `event.sender_id`, `event.out`,
  `event.is_reply`, `await event.get_reply_message()`, `await event.reply(...)`, `await event.edit(...)` и т. д.
- `context` в `@on_error` — `{'module': ..., 'function': ...}`.
- `number` в `@on_account_switch` — номер телефона из `accounts.json`.
- Хэндлер на «только свои» данные при `@on_load` фильтрует так: `if module_info.module_name != MODULE_NAME: return`.

## 22. engine — справочник

`engine` — это сам объект `Core`. Синхронные функции помечены, остальное — корутины (`await`).

### Сообщения

```python
await engine.answer(message, text, file=None)        # правит message (если это ваше сообщение), иначе отвечает новым
await engine.reply(message, text, file=None)         # всегда новое сообщение-ответ
await engine.noreply(message, text, file=None)       # в тот же чат, без ответа
await engine.send_message(chat_id, text, file=None)  # в любой чат по id
engine.get_args()                                     # СИНХРОННО: аргументы текущей команды строкой ('' вне события)
```

- `answer` — паттерн «ожидание → результат»: первый `answer(event, "…")` на вашу команду правит саму команду,
  следующий — то же сообщение.
- Текст — HTML (`parse_mode='html'`) и проходит `safe_html()`: настоящие теги Telegram работают,
  `<не_теги>` и одиночные `<`, `&` показываются как есть ([раздел 34](#34-безопасный-html-safe_html)).
- `file` — путь на диске или id/имя из реестра `files`.
- `send_message`/`noreply` сами находят пользователя или чат «вне кэша» Telethon (диалоги, контакты,
  участники) и бросают понятный `RuntimeError`, если найти не удалось.

### Префикс, версия, клиент

```python
await engine.get_prefix()            # текущий префикс (БД, по умолчанию из config)

engine.config                        # dict из user/config.json (тот же объект, что у main.py)
```

## 23. db и cache — хранилища

`import db` — постоянное хранилище (JSON-файл `user/data/database.json`, пишется на диск при каждом
`set`/`delete`). `import cache` — **тот же интерфейс** в памяти, стирается при перезапуске. `cache` — для
временного состояния (черновики, передача данных между хэндлерами формы), `db` — для всего, что должно
пережить перезапуск.

```python
await db.set(key, value)               # реальный ключ: "<MODULE_NAME>:key"
value = await db.get(key, default=None)
await db.delete(key)
data = await db.list(modulename=None)  # все ключи модуля (по умолчанию текущего) без префикса -> dict

await db.gset('other_module:key', value)   # «сырой» ключ без префикса — доступ к чужим данным
await db.gget('other_module:key', default=None)
await db.gdelete('other_module:key')
data = await db.glist(prefix=None)         # все ключи по префиксу (или вся БД) -> dict
```

- Значения должны сериализоваться в JSON (`dict`, `list`, `str`, числа, `bool`, `None`).
- `get/set/delete/list` используют текущий модуль из контекста и работают только внутри хэндлеров; вне
  контекста — `RuntimeError`. Там используйте `g*`-версии с явным префиксом.
- Файл БД человекочитаем, но не правьте его руками при работающем юзерботе — при следующем `set()` он
  перезапишется из памяти.
- Служебные ключи ядра: `core:prefix`, `core:loaded_modules`, `core:files:<id>`, `<module>:__config__`
  (настройки), `core:form_media`.

## 24. Настройки модуля: create_config и др.

Настройки — публичные, типизированные параметры модуля, которые пользователь меняет через `.config` и на
сайте. Хранятся в БД под `"<MODULE_NAME>:__config__"`.

```python
value = await engine.create_config(
    key='greeting',
    description='Текст после ответа .ping',
    data_type='str',             # 'str' | 'int' | 'float' | 'bool' | 'list' | 'choice' | 'choices'
    default='на связи!',
    valid=None,                  # ограничения (ниже)
    options=None,                # варианты для choice/choices
)
value = await engine.get_config('greeting')                    # текущего модуля
value = await engine.get_config('greeting', module_name='ping')  # чужого
await engine.edit_config('greeting', 'edit', 'новое')          # str/int/float/bool/choice
await engine.edit_config('chats', 'add', -100123)              # list/choices: добавить
await engine.edit_config('chats', 'del', -100123)              # list/choices: удалить
await engine.edit_config('greeting', 'to_default')             # любой тип: вернуть default
await engine.delete_config('greeting')                         # удалить одну настройку
```

- **`create_config()` с существующим ключом не перезаписывает значение** — просто возвращает текущее.
- **Вызывайте `create_config()` при каждом запуске** (в `@on_start` или в `@on_load` с фильтром «это я»):
  при старте движок удаляет из БД настройки, которые модуль в этом запуске не объявил (переименованные и
  удалённые в коде).
- **`valid=`**: для `int`/`float` — `{'min_value': 0, 'max_value': 5}`, для `str` — `{'min_len': 1,
  'max_len': 32}` (любой ключ пары можно опустить). Проверяются `default` и каждый `edit`; нарушение —
  `ValueError` с понятным текстом. Для `bool`, `list`, `choice`, `choices` не поддерживается.
- **`choice`** — `options` обязателен, `default` — один из вариантов, меняется `'edit'`.
  **`choices`** — `default` — непустой список вариантов, меняется `'add'`/`'del'`, снять последний нельзя.
  Значения задаются самими элементами, не номерами. Если модуль поменял `options` в коде, при следующем
  `create_config()` они обновятся.
- Неверная операция для типа — `ValueError`; нет ключа — `KeyError`.

```python
@decorators.on_load()
async def _setup(module_info):
    if module_info.module_name != MODULE_NAME:
        return
    await engine.create_config('retries', 'Сколько раз повторять', 'int', 3, valid={'min_value': 1, 'max_value': 5})
    await engine.create_config('mode', 'Режим', 'choice', 'быстро', options=['быстро', 'точно'])
```

## 25. waiters — дождаться сообщения

```python
waiters.wait_message(chat_id=None, user_id=None, timeout=None)   # СИНХРОННО возвращает Waiter
```

- **`chat_id`**: `None` — текущий чат (где вызвана команда; без события — `RuntimeError`); `'me'` —
  «Избранное»; число — конкретный чат; список — любой из.
- **`user_id`**: `None` — от **любого**, в том числе от вас (Telegram присылает и ваши исходящие); `'me'` —
  только от владельца; число; список.
- **`timeout`**: секунды; `None` — настройка `default_timeout` модуля Waiters (60 с). Бесконечного ожидания
  нет — для долгого передайте большое число.

`Waiter` работает двумя способами:

```python
try:
    msg = await waiters.wait_message(user_id='me', timeout=30)      # одно сообщение
except TimeoutError:
    await engine.answer(event, "не дождался")

async for msg in waiters.wait_message(timeout=120):                 # цикл: ждёт, выполняет тело, снова ждёт
    if msg.raw_text == 'стоп':
        break
    await engine.reply(msg, f"эхо: {msg.raw_text}")
else:
    await engine.answer(event, "тишина затянулась")                 # цикл кончился по таймауту, не через break
```

**Отмена извне** — сохраните сам `Waiter` (до `await`) и вызовите `waiter.cancel()` из другого хэндлера:
одиночный `await` бросит `waiters.WaiterCancelled`, `async for` просто закончится. Ожидание вешает
временный обработчик на клиент и снимает его по завершении — основному диспетчеру не мешает.

> Без фильтра `user_id` ожидание поймает и ваше собственное следующее сообщение — в том числе ответ, который
> модуль сам отправил в этот чат. Указывайте `user_id='me'` или id собеседника.

## 26. files — реестр файлов

Реестр поверх БД: метаданные (`id`, `path`, `name`, `type`, `size`) — в ключах `core:files:<id>`, сами
файлы — в `user/data/files/`.

```python
obj = await files.download_reply_file(message)
# {'id': '1a2b3c4d5e6f', 'path': 'user/data/files/photo.jpg', 'name': 'photo.jpg', 'type': 'image/jpeg', 'size': 12345}
# ValueError — message не ответ или в ответе нет файла

obj = await files.create_file('text/plain', 'report.txt', 'содержимое')   # (тип, имя, str | bytes) -> dict
obj = await files.get_file(query='report.txt', ftype=None)   # совпадение query с id, name, path или size -> dict | None
ok = await files.delete_file(file_id='1a2b3c4d5e6f')         # или path=...; удаляет запись и файл -> bool
```

`file=` в `engine.answer/reply/noreply/send_message` и `engine.bot.*` принимает путь на диске или
id/имя/путь из реестра; `engine.bot.*` — ещё и готовый `aiogram.types.InputFile`.

## 27. Инлайн-формы

Инлайн-форма — сообщение «via @ваш_бот» с кнопками, которым управляет юзербот: текст и кнопки можно
менять сколько угодно раз, клики и ввод приходят в обработчики модуля. Работает в любом чате, где вы пишете.
Нужен стационарный бот с инлайн-режимом и инлайн-фидбэком 100 % (Startup включает их сам).

### Быстрый пример

```python
@decorators.command('vote')
async def vote_cmd(event):
    """голосование с кнопками"""
    votes = {'yes': 0, 'no': 0}
    form = await engine.create_inlineform(
        event.chat_id, "Идём?",
        buttons=[[("Да", "yes"), ("Нет", "no")], [("Закрыть", "close")]],
        for_user=event.chat_id if event.chat_id < 0 else None,   # в группе — все участники
        timeout=600,
    )

    @form.on_click(data='close')
    async def _(click):
        await form.close()

    @form.on_click()                       # без фильтра — любой клик (сработает и на close, поэтому проверяем)
    async def _(click):
        if click.data not in votes:
            return
        votes[click.data] += 1
        await click.answer("Голос учтён")
        await form.edit(f"Идём?\nда: {votes['yes']} · нет: {votes['no']}",
                        buttons=[[("Да", "yes"), ("Нет", "no")], [("Закрыть", "close")]])
```

### create_inlineform

```python
form = await engine.create_inlineform(
    chat_id, text, buttons=None,
    for_user=None, black_list=None, timeout=None, reply_to=None, media=None,
)
```

| Параметр | Смысл |
|---|---|
| `buttons` | список рядов `[[("Ок", "ok")], [("Да", "yes"), ("Нет", "no")]]` или один ряд без обёртки `[("Ок", "ok"), ("Да", "yes")]`; в рядах можно смешивать `(текст, callback_data)` и `engine.InputButton(...)` |
| `for_user` | кто может нажимать: `None` или `'me'` — только владелец; положительный id — пользователь; **отрицательный id — все участники этого чата/канала**; список — любое совпадение |
| `black_list` | id или список id, кому нельзя никогда (проверяется раньше `for_user`) |
| `timeout` | секунд **без кликов**, после которых форма закроется сама; `None` — живёт, пока модуль не вызовет `form.close()` |
| `reply_to` | `None` — если команда была ответом на сообщение, форма тоже отвечает на него; `False` — не отвечать; число — id сообщения |
| `media` | картинка или анимация над текстом: путь, `http(s)`-ссылка или `file_id` бота. `.jpg/.png/.webp` — картинка, `.mp4/.gif/.webm` — анимация (как GIF, без звука). Текст становится подписью (до 1024 символов). Файл загружается ботом один раз, дальше берётся из кэша |

Ошибки: нет бота — `RuntimeError`; у бота выключен инлайн-режим — `RuntimeError` с подсказкой; бот не
подтвердил форму за `confirm_timeout` секунд — `TimeoutError` (почти всегда — нет инлайн-фидбэка 100 %).
Вызывать нужно изнутри хэндлера модуля (форма принадлежит модулю и закрывается при его выгрузке).

### Объект формы

```python
@form.on_click(data=None, data_startswith=None)   # обработчик клика; без фильтра — любой клик
async def _(click): ...

@form.on_input(data=None)                         # обработчик ввода через InputButton
async def _(inp): ...

await form.edit(text, buttons=None)               # переписать текст и кнопки (None — убрать кнопки)
await form.close(remove_buttons=True)             # прекратить обработку; сообщение остаётся в чате
form.chat_id, form.text, form.page, form.owner_module, form.for_user, form.black_list, form.media
```

- Обработчиков можно вешать сколько угодно, с разными фильтрами; `data` и `data_startswith` вместе —
  `ValueError`. Если ни один не подошёл, движок сам снимает «часики» у кнопки.
- `form.edit()` на закрытой форме — `RuntimeError`. Чтобы оставить кнопки как есть при смене текста,
  передайте `buttons=form._raw_buttons`.
- Внутри обработчика работают `db`, `cache`, `engine.get_config` (контекст — модуль-владелец формы), но
  `current_event` пуст: если нужен исходный `event` (например, для `exec_modcmd`), возьмите его из замыкания.

| Объект | Поля |
|---|---|
| `InlineClick` | `.data`, `.from_user` (`telethon.types.User` или `None`), `.chat_id`, `.inline_message_id`, `await .answer(text=None, show_alert=False)` |
| `InlineInput` | `.data` (ключ поля), `.value` (введённый текст), `.from_user`, `.chat_id`, `.form` |
| `InputButton(text, data, hint="Enter value...", for_user=None)` | кнопка «введите значение» |

Кнопка-ссылка — `('Открыть', 'url:https://example.com')`: открывает адрес (также `http://`, `tg://`), в `on_click` не
приходит; на сайте (Emulate, Sandbox) рисуется ссылкой.

`callback_data` — не длиннее 64 байт (ограничение Bot API). Объёмные данные храните в `cache`/`db` под
коротким ключом и кладите в кнопку только ключ.

### InputButton — поле ввода в форме

```python
form = await engine.create_inlineform(
    event.chat_id, "Как вас зовут?",
    buttons=[[engine.InputButton("Ввести имя", "name", hint="")]],
)

@form.on_input(data='name')
async def _(inp):
    await form.edit(f"Привет, {engine.safe_html(inp.value)}!", buttons=None)
```

Тап по кнопке переключает поле ввода пользователя на `@бот <hint>`; пользователь печатает значение и
выбирает единственный инлайн-результат — значение приходит в `on_input`, а сообщение с ним движок тут же
удаляет. Особенности:

- на одного пользователя одновременно ждёт только **одна** `InputButton` (ограничение клиента Telegram);
  новая регистрация перекрывает старую;
- `for_user` у кнопки — только конкретные люди (без отрицательных id чатов);
- ввод разовый: чтобы ждать снова (например, значение не прошло проверку), повесьте кнопку заново через
  `form.edit(...)`;
- нужен инлайн-фидбэк 100 % (как и для самой формы).

**Альтернатива — обычное сообщение.** Держите форму открытой со статусом «пришлите ответом…» и ждите
сообщение через `waiters.wait_message(chat_id=click.chat_id, user_id=click.from_user.id, timeout=120)`. Так
можно вести сколько угодно параллельных мастеров, пользователю не нужен инлайн-режим, но его сообщение
останется в чате (удалите его сами: `await msg.delete()`). На этом построен мастер добавления аккаунта.

### Страницы

**Автоматически.** Больше 100 кнопок (`MAX_BUTTONS_PER_PAGE`) — движок сам режет их на страницы по границам
рядов и добавляет ряд навигации ◂ `N/M` ▸; клики по нему обрабатывает сам, ваши `on_click` их не видят.
Смена страницы меняет только клавиатуру; `InputButton` на новой странице регистрируются заново.

**Выбор из списка по 7** — `engine.picker_page()`:

```python
items = [(name, f"pick:{name}") for name in names]
rows, page, total = engine.picker_page(items, page=0, per_page=7, page_callback="pg:")
rows.append([("Назад", "back")])
await form.edit("Выберите:", buttons=rows)

@form.on_click(data_startswith="pg:")
async def _(click):
    rows, page, total = engine.picker_page(items, int(click.data.split(":", 1)[1]), 7, "pg:")
    rows.append([("Назад", "back")])
    await form.edit("Выберите:", buttons=rows)
```

Каждый элемент — свой ряд; ряд навигации добавляется, только если страниц больше одной; номер целевой
страницы зашит в `callback_data` ◂/▸, навигацию обрабатывает модуль.

### Как это работает внутри

1. `create_inlineform()` создаёт случайный `form_id` и ждёт подтверждения.
2. Юзербот делает инлайн-запрос к своему боту с `form_id` (как если бы вы набрали `@бот <form_id>`), бот
   отвечает одним результатом сразу с текстом и кнопками формы (чужие инлайн-запросы получают пустой ответ).
3. Юзербот «выбирает» результат — в чат уходит сообщение «via @бот».
4. Telegram присылает боту `chosen_inline_result` с `inline_message_id` (**только при инлайн-фидбэке 100 %**) —
   форма подтверждена, модуль получает объект `InlineForm`.
5. Клики приходят боту как `callback_query` с `inline_message_id`; движок проверяет доступ (`black_list`,
   `for_user`, членство в чате — сначала ботом, потом аккаунтом, с кэшем `member_cache_ttl`), применяет общий
   лимит `clicks_per_second`, находит пользователя и вызывает подходящие `on_click`.

Обслуживание — модуль InlineStuff (`.forms`, `.closeform`, настройки `confirm_timeout`, `member_cache_ttl`,
`clicks_per_second`).

## 28. Стационарный бот в модулях: import bot, inline_function, engine.bot

### import bot — хэндлеры бота рядом с хэндлерами юзербота

```python
import engine
import decorators
import bot

@decorators.command('ping')
async def ping_userbot(event):
    await engine.answer(event, 'Pong (юзербот)')

@bot.command('ping', access='public')
async def ping_bot(event):
    await event.reply('Pong (бот)')
```

| Декоратор | Когда | Сигнатура |
|---|---|---|
| `@bot.command('cmd', ..., access='public', for_user=None, for_chat=None, black_list=None, black_chats=None)` | `/cmd` в чате с ботом (префикс всегда `/`, `@имя_бота` в конце допускается) | `async def f(event)` |
| `@bot.inline_function('name', ..., те же параметры доступа)` | `@бот name аргументы` в любом чате (ниже) | `async def f(event, args)` |
| `@bot.watcher(watch='bot', access='public')` | сообщения: `'bot'` — которые видит бот, `'userbot'` — которые видит аккаунт, `'all'` — оба (одно сообщение — один вызов) | `async def f(event)` |
| `@bot.on_start()` | после запуска юзербота **и** подключения бота | `async def f()` |
| `@bot.on_load()` | загрузка любого модуля | `async def f(module_info)` |
| `@bot.cycle(interval='1m')` | периодически, пока бот подключён | `async def f()` |
| `@bot.telegram_event()` | изменение статуса бота в чате (`my_chat_member`) и участников (`chat_member`) | `async def f(event)` |
| `@bot.on_error()` | исключение в любом `bot.*`-хэндлере | `async def f(error_text, context)` |

- **`access`**: `'public'` — кто угодно; `'self'` — только владелец юзербота. Чужой вызов `self`-хэндлера
  молча игнорируется.
- **`for_user` / `for_chat` / `black_list` / `black_chats`** (у `command` и `inline_function`) — id или
  списки: ничего не задано — всем и везде; только `for_user` — этим людям в любом чате; только `for_chat` —
  всем, но в этих чатах; оба — оба условия; `black_*` запрещают всегда.
- Встроенные команды бота (`/start`, `/status`) главнее модульных: если бот уже подключён, модуль с такой командой
  не загрузится, иначе его команда просто не будет вызываться. Занятый
  другим модулем алиас — `ValueError` при загрузке.
- Без `aiogram_token` `bot.*`-хэндлеры не вызываются.
- `bot.callback()` на уровне модулей не подключается — клики по кнопкам обычных сообщений бота обрабатывайте
  хэндлером прямо в `aiobot/bot.py`, клики по формам — через `form.on_click`.

**Событие всегда в стиле Telethon.** Сообщения, пойманные аккаунтом, — настоящие события Telethon;
сообщения бота оборачиваются в `BotMessageEvent` (`core/bot_events.py`): `.raw_text`, `.text`,
`.sender_id`, `.chat_id`, `.out`, `.is_private`, `.is_group`, `await .reply()`, `.respond()`, `.edit()`,
`.delete()`, `.download_media()`, `.raw` (исходный `aiogram.types.Message`; остальные атрибуты
проксируются в него). У `telegram_event` — `BotChatMemberEvent`: `.chat_id`, `.user_id`, `.old_status`,
`.new_status`, `.user_joined`, `.user_left`, `.is_bot_event`. У всех — `.origin`: `'bot'` или `'userbot'`.

Пример целиком — `examples/hybrid_bot_demo.py`.

### bot.inline_function — функции через инлайн-режим

Любой человек в любом чате набирает `@имя_бота имя_функции аргументы`:

```python
@bot.inline_function('weather', access='public')
async def weather_inline(event, args):
    """прогноз погоды: <город>"""
    await event.reply(f"Погода в {args or 'Москве'}: …")
```

Пока имя набирается, бот подсказывает функции по префиксу (с первой строкой докстринга); когда первое
слово точно совпало — остальное считается аргументами. После отправки в чат уходит сообщение
«⚙️ weather Москва via @бот»; **его видит и обрабатывает юзербот** (Bot API не сообщает, в каком чате
выбран инлайн-результат). Поэтому `event` — всегда настоящее событие Telethon, а функция работает только в
чатах, где состоит ваш аккаунт.

### engine.bot — сообщения от имени бота

```python
await engine.bot.send_message(chat_id, "Привет", file=None, buttons=[[("Ок", "ok")]], reply_to=None)
await engine.bot.reply(aiogram_message, "Принято", file=None, buttons=None)
await engine.bot.edit(aiogram_message, "Обновлено", file=None, buttons=None)
engine.bot.raw                       # aiogram.Bot — любые методы Bot API
await engine.bot_send_to_owner(text, file=None, buttons=None)
```

- `message` в `reply/edit` — `aiogram.types.Message` (не Telethon).
- `file`: `.jpg/.jpeg/.png/.webp/.gif` уходят фото, остальное — документом. `edit(..., file=...)` удаляет
  старое сообщение и отправляет новое (Bot API не превращает текст в медиа).
- Без бота — `RuntimeError`.
- **`bot_send_to_owner`** — ЛС владельцу. Бот не может писать первым, а владелец мог занести его в ЧС —
  тогда юзербот сам снимает бота с ЧС, пишет ему `/start` и бот повторяет отправку (до 5 попыток). Не вышло —
  `RuntimeError` (в «Избранное» не откатывается). Лимит файла — 50 МБ.

### Хэндлеры прямо в aiobot/bot.py

В `aiobot/bot.py` можно объявлять «сырые» хэндлеры теми же декораторами (`from . import decorators as bot`,
`@bot.command(...)`, `@bot.callback(access=...)`, …) — они получают исходные объекты aiogram и
подключаются сами (`register_decorated_handlers`). Для более сложной логики — свои `aiogram.Router` через
`dp.include_router(...)` в `create_bot()`.

## 29. Гости и алиасы в модулях: engine.access, engine.aliases

Команду модуля может запустить не только владелец, но и гость с доступом ([раздел 11](#11-доступ-для-других-людей-и-алиасы)).
Большинству модулей ничего менять не нужно — движок делает поведение одинаковым:

| Что | По команде владельца | По команде гостя |
|---|---|---|
| `event.out`, `event.sender_id` | `True`, владелец | `False`, гость |
| `engine.answer(event, …)` | правит команду | первый вызов отвечает на сообщение гостя, следующие правят этот ответ |
| `waiters.wait_message(user_id='me')` | ждёт владельца | ждёт **гостя** (того, кто запустил команду); `chat_id='me'` — всегда «Избранное» владельца |
| `create_inlineform(for_user=None)` | кнопки — владельцу | владельцу и гостю |
| клик гостя по форме | — | обработчик выполняется «от имени гостя»: `engine.guest_id()` = id гостя |
| `load/unload/kill/reload/restore_module`, `set_account`, `request_shutdown`, `edit_prefix` | работают | работают, если их вызывает модуль-хозяин действия (`loader`, `account_manager`, `systemkeeper`/`backup`, `config`) или гостю выдан такой модуль целиком; иначе `PermissionError` |
| `engine.exec_modcmd(...)` | без проверок | проверяет выдачи гостя на целевую команду, иначе `PermissionError` |

```python
engine.guest_id()           # id гостя, по чьей команде или клику сейчас выполняется код; None — действует владелец

@decorators.command('whoami')
async def whoami(event):
    """кто запустил команду"""
    gid = engine.guest_id()
    await engine.answer(event, "владелец" if gid is None else f"гость {gid}")
```

**API доступа** (`engine.access`, `core/access.py`) — для модулей, которые хотят что-то показать или проверить:

```python
engine.access.users()                     # {'<id>': {'name', 'username', 'class', 'scopes', 'modules', 'commands', 'added'}}
engine.access.classes()                   # {'FULL': {'title', 'description', 'scopes', 'modules', 'commands', 'system'}, ...}
engine.access.get_user(user_id)           # запись или None
engine.access.check(user_id, module, 'module:команда', is_builtin)   # (bool, причина)
engine.access.module_allowed(user_id, module, is_builtin)          # выдан ли модуль целиком: (bool, причина)
engine.access.grants_of(obj)              # [('scope'|'module'|'command', значение), ...] у класса или пользователя
await engine.access.grant('user' | 'class', ident, 'scope' | 'module' | 'command', value)
await engine.access.revoke('user' | 'class', ident, kind, value)
await engine.access.set_user_class(user_id, 'LOADED' | None)
await engine.access.remove_user(user_id)  # отозвать весь доступ
await engine.access.create_class(idn, title='', description='', copy_from=None)
await engine.access.update_class(idn, title=None, description=None)
await engine.access.rename_class(idn, new_idn)
await engine.access.delete_class(idn)
engine.module_danger(module)              # почему доступ к модулю критически опасен; [] — не опасен
```

Выдачи: `scope` — `'all'`, `'builtin'` или `'loaded'`; `module` — `MODULE_NAME`; `command` — ключ
`"MODULE_NAME:первое_имя"` (первый аргумент `@decorators.command(...)`), например `"ping:dping"`. Пользователь без
класса и без выдач из списка убирается сам. Ошибки управления — `core.access.AccessError` с понятным текстом.
Данные — в БД под `core:access`.

**Алиасы** (`engine.aliases`): `all()`, `get(name)`, `await set(name, command, args='', existing_commands=set(engine.command_map))`,
`await delete(name)`, `expand(name, rest)` → `(команда, аргументы)`. Команда, запущенная через алиас, получает
событие-прокси: `engine.get_args()` и `event.raw_text` уже содержат целевую команду и итоговые аргументы.

## 30. visual — иконки и оформление

`import visual`. Единый стиль сообщений: 🟥 — заголовок, 🟧 — раздел, остальное — тонкие символы; значения
моноширинным. Готовые помощники собирают сообщение в этом стиле:

```python
await engine.answer(event, "\n".join([
```

## 33. Ошибки и логи: on_error, tlog, botlog

### Ошибки

Любое исключение в `@command`, `@watcher`, `@cycle`, `@telegram_event`, `@callback`, в обработчиках форм и
страниц сайта перехватывается движком:

1. в терминал: `[ERROR] модуль=<module> функция=<func>: <Тип>: <текст>`;
2. текст и контекст передаются **всем** `@decorators.on_error()` всех модулей (Logging пересылает их в ЛС).

```python
@decorators.on_error()
async def _errors(error_text, context):
    if context['module'] == MODULE_NAME:
        engine.botlog(error_text, level='error', function=context['function'])
```

Ошибка внутри самого `@on_error` только пишется в терминал (без рекурсии). Ошибки `bot.*`-хэндлеров идут в
`@bot.on_error()`. Сломанный хэндлер не мешает остальным; ошибка на этапе загрузки файла модуля — модуль
просто не загружается.

### tlog и botlog

```python
engine.tlog("текст")                                   # в терминал (и во вкладку логов сайта)
engine.botlog("Синхронизировано: <b>3</b>")            # в ЛС через бота; синхронно, можно без await
status = await engine.botlog("Сбой API", level="error")  # 'sent' | 'dropped' | 'failed' | 'disabled' | 'no_bot'
engine.botlog("…", module="x", function="y")           # явно задать модуль/функцию
engine.botlog_raw(html)                                # готовое HTML-сообщение, только лимитер и доставка
```

`botlog` оформляет сообщение: заголовок по уровню (`info`/`success` — «Лог», `warning` — «Предупреждение»,
`error` — «Ошибка»), модуль (из контекста), функция (откуда вызван), время и внизу ваш текст (HTML допустим,
не-теги экранируются, длиннее ~3400 символов — обрезается). Возвращает `asyncio.Task`; вне event loop —
`None` и печать в терминал. Бота нет — текст уходит в терминал. Куда шлётся — `log_chat_id` модуля Logging
(`0` — ЛС), выключатель — `Logging.enabled`.

**Лимитер** (`core/botlog.py`) — ведро токенов плюс очередь: до `botlog_burst` сообщений уходят сразу, дальше
одно каждые `botlog_interval` секунд; лишние ждут в очереди (до `botlog_queue`), а при переполнении или
`botlog_wait=False` сжигаются — потом приходит одно сводное «пропущено N». Неудачная отправка не бросает
исключение (статус `'failed'`).

## 34. Безопасный HTML: safe_html

Bot API отклоняет любой `<...>`, который не является тегом Telegram (`can't parse entities: Unsupported start
tag`), а Telethon молча выбрасывает такой «тег» вместе с содержимым. В описаниях команд и настроек такое
встречается постоянно (`<имя_модуля>`, `<chat_id>`). Поэтому весь исходящий HTML проходит
`safe_html(text)` (`core/html_utils.py`, доступен как `engine.safe_html`):

| В тексте | Результат |
|---|---|
| теги Telegram: `b strong i em u ins s strike del tg-spoiler code pre blockquote a span tg-emoji` — с допустимыми атрибутами, корректно закрытые | остаются |
| `<имя_модуля>`, `<br>`, `<b class="x">`, `<a>` без `href` | показываются буквально (`&lt;…&gt;`) |
| лишний `</b>`, перепутанная вложенность, незакрытый тег | эти теги — буквально, остальной текст цел |
| одиночные `<`, `>`, `&` | экранируются |
| готовые сущности `&lt; &gt; &amp; &quot; &#123;` | не трогаются |

Функция идемпотентна. Применяется автоматически в `engine.answer/reply/noreply/send_message` и в каждом
запросе стационарного бота с HTML-разметкой (`FRXBot`). Сами вызывать её нужно, когда вставляете в текст
чужие данные, которые должны показаться буквально, — или используйте `html.escape()`.

## 35. Страницы сайта из модулей: import web

Модуль описывает страницу обычной функцией — без HTML и JS; страница появляется в меню сайта.

```python
import web

@web.page("Статистика", icon="✦")
async def stats_page(ui):
    ui.title("Статистика")
    ui.text(f"Нажатий: {ui.state.get('n', 0)}")
    ui.input("name", label="имя", placeholder="как вас зовут")
    ui.toggle("loud", label="громко")
    ui.select("color", ["red", "blue"], label="цвет")
    with ui.row():
        ui.button("плюс", on_click=inc, arg=2)
        ui.button("сброс", on_click=reset, danger=True)

async def inc(ctx):
    ctx.state['n'] = ctx.state.get('n', 0) + ctx.arg
    ctx.toast(f"Привет, {ctx.values.get('name') or 'аноним'}!", 'ok')
    ctx.set_value('name', '')

async def reset(ctx):
    ctx.state.clear()
```

- Функция страницы (`ui`, sync или async) **вызывается заново** при открытии и после каждого клика: стройте
  интерфейс от `ui.state` (dict страницы, живёт до перезапуска) и `ui.values` (значения полей).
- Компоненты: `title`, `text`, `muted`, `code`, `divider`, `input(name, label, value, placeholder, secret,
  multiline)`, `toggle(name, label, value)`, `select(name, options, label, value)`, `button(label, on_click,
  arg, danger)`, `row()` и `section(title)` (через `with`), `list(items)`, `table(headers, rows)`.
- Обработчик кнопки получает `ctx`: `ctx.values`, `ctx.arg`, `ctx.state`, `ctx.toast(text, kind='info'|'ok'|'error')`,
  `ctx.set_value(name, value)`. Исключение показывается на странице красным, сайт не падает.
- Страница выполняется в контексте модуля (`db`, `engine.get_config` работают), `current_event` нет.
- Страницы регистрируются при загрузке модуля и исчезают при выгрузке. Данные попадают в браузер только как
  текст.

## 38. Полный пример модуля

Модуль-напоминалка: `.remind <минуты> <текст>` ставит напоминание, `.reminders` показывает активные.
Напоминания хранятся в `db` и **переживают перезапуск**: при старте модуль поднимает их заново.

```python
"""
Напоминания: .remind <минуты> <текст>, .reminders
"""
import asyncio
import html
import time

import engine
import decorators
import visual
import db
import cache

NAME = "Напоминалка"
MODULE_NAME = "reminder"
VERSION = "1.0"
AUTHOR = "Вы"
DESCRIPTION = "Одноразовые напоминания по таймеру"

@decorators.on_start()
async def _start():
    """настройки и восстановление напоминаний после перезапуска"""
    await engine.create_config('max_minutes', 'Максимальная задержка, минут', 'int', 1440,
                               valid={'min_value': 1, 'max_value': 10080})
    for rid, r in (await db.get('active', {})).items():
        await _schedule(rid, r['chat_id'], r['text'], max(0, r['at'] - time.time()))


async def _schedule(rid, chat_id, text, delay):
    # задачи держим в cache: он переживает .reloadmod, поэтому повторный запуск не плодит дубли
    tasks = await cache.get('tasks', {})
    old = tasks.get(rid)
    if old is not None and not old.done():
        old.cancel()
    tasks[rid] = asyncio.create_task(_fire(rid, chat_id, text, delay))   # контекст модуля копируется в задачу
    await cache.set('tasks', tasks)


async def _fire(rid, chat_id, text, delay):
    await asyncio.sleep(delay)
    await engine.send_message(chat_id, visual.warn(f"<b>Напоминание:</b> {html.escape(text)}"))
    active = await db.get('active', {})
    active.pop(rid, None)
    await db.set('active', active)
    (await cache.get('tasks', {})).pop(rid, None)


@decorators.command('remind', 'напомни')
async def remind_cmd(event):
    """поставить напоминание: <минуты> <текст>"""
    parts = engine.get_args().split(maxsplit=1)
    if len(parts) < 2 or not parts[0].isdigit():
        await engine.answer(event, visual.err("Формат: .remind <минуты> <текст>"))
        return
    minutes, text = int(parts[0]), parts[1]
    limit = await engine.get_config('max_minutes')
    if not 1 <= minutes <= limit:
        await engine.answer(event, visual.err(f"Задержка — от 1 до {limit} минут"))
        return
    rid = f"{event.chat_id}:{event.id}"
    active = await db.get('active', {})
    active[rid] = {'chat_id': event.chat_id, 'text': text, 'at': time.time() + minutes * 60}
    await db.set('active', active)
    await _schedule(rid, event.chat_id, text, minutes * 60)
    await engine.answer(event, visual.ok(f"Напомню через {minutes} мин.") + "\n" + visual.hint(html.escape(text)))


@decorators.command('reminders')
async def reminders_cmd(event):
    """активные напоминания в этом чате"""
    mine = [r for r in (await db.get('active', {})).values() if r['chat_id'] == event.chat_id]
    if not mine:
        await engine.answer(event, visual.wait("Активных напоминаний нет"))
        return
    lines = [visual.title("Напоминания")]
    for r in sorted(mine, key=lambda r: r['at']):
        left = max(0, int((r['at'] - time.time()) // 60))
        lines.append(visual.item(f"через {left} мин — {html.escape(r['text'])}"))
    await engine.answer(event, "\n".join(lines))


@decorators.on_error()
async def _errors(error_text, context):
    """только свои ошибки — в ЛС через бота"""
    if context['module'] == MODULE_NAME:
        engine.botlog(error_text, level='error', function=context['function'])
```

Что здесь показано: метаданные; настройка с ограничением (`create_config` при каждом старте); аргументы
команды (`engine.get_args()`); постоянное хранение в `db` и восстановление в `@on_start`; `cache` для
объектов, которые должны жить в памяти между перезагрузками модуля; оформление через `visual`;
экранирование пользовательского текста; свой `@on_error` с `botlog`. Учтите: движок отменяет при выгрузке
только задачи `@cycle` — задачи, созданные через `asyncio.create_task`, модуль отменяет сам.

Проверить модуль можно, не трогая Telegram: откройте его на сайте в WebIDE и запустите в Sandbox
(`Ctrl+Enter`) — там можно сдвинуть виртуальное время и увидеть срабатывание напоминания.

## 39. Типичные ошибки и FAQ

**`TimeoutError` при первом же `create_inlineform()`.** У бота не включён инлайн-фидбэк 100 %. Startup
включает его при запуске — перезапустите юзербот; вручную: @BotFather → `/setinlinefeedback` → бот → `100%`.
`BotInlineDisabledError` / «выключен инлайн-режим» — то же самое с `/setinline`.

**Команда не срабатывает.** Команды работают только с вашего аккаунта (исходящие сообщения) и только с
текущим префиксом. Чужие сообщения видят лишь вотчеры.

**`Модуль с MODULE_NAME='…' уже загружен` / `Команда '…' уже занята модулем '…'`.** `MODULE_NAME` и алиасы
команд должны быть уникальны во всём юзерботе; конфликтующий модуль не загружается целиком. `NAME` может
повторяться. Чтобы обновить модуль, поднимите `VERSION`.

**`db.get/db.set вызваны вне контекста модуля`.** Вызов не из хэндлера (например, на верхнем уровне файла
или в коллбэке сторонней библиотеки). Перенесите в `@on_load`/`@on_start` или используйте
`db.gget('мой_модуль:ключ')`.

**Настройка пропала после перезапуска.** `create_config()` должен вызываться при каждом запуске — иначе
движок считает настройку устаревшей и удаляет её.

**`wait_message()` поймал моё же сообщение.** По умолчанию `user_id=None` — сообщение от кого угодно,
включая вас и ответы самого модуля. Укажите `user_id='me'` или id собеседника.

**Вместо `<имя>` в тексте — пусто или ошибка парсинга.** Через `engine.answer` и бота такого не бывает:
не-теги экранируются автоматически. Если вы шлёте через `engine.client.send_message` напрямую — оберните
текст в `engine.safe_html()`.

**`@decorators.on_start()` не может отправить сообщение ботом.** В момент `on_start` бот ещё не подключён —
используйте `@bot.on_start()`.

**Модуль завис.** `engine.kill_module('имя')` перезапускает модуль из памяти (сбрасывает его состояние);
`.reloadmod имя` — перечитывает файл с диска.

**Я поправил файл модуля руками.** `.reloadmod <модуль>` — без перезапуска юзербота. Файлы ваших модулей —
`user/modules/`.

**Как вернуть выгруженный модуль?** `.restoremods` → карточка → «Восстановить». Или перенесите файл из
`user/modules/unloaded/` в `user/modules/` и `.restart`.

**Можно ли сторонние pip-пакеты в модулях?** Да, обычным `import` после `pip install` в то же окружение,
где запущен FRX.

**Куда класть свои файлы и картинки?** Данные — `user/data/` (например, `files.create_file()` или свой
подкаталог через `from core.paths import DATA_DIR`). Картинки для `engine.asset_path()` — `user/assets/`
(или вкладка files сайта).

**Как запустить несколько юзерботов?** Один код, разные папки данных: `FRX_USER_DIR=/путь python
frx_systemkeeper.py`, у каждого свой `web_port`.

**Как сменить префикс?** `.eval await engine.edit_prefix('!')` (или свой модуль с командой на
`engine.edit_prefix`).

**Как перенести FRX на другую машину?** Скопируйте папку `user/` (или сделайте `.createbackup` и
`.restorebackup` на новой установке). Код берите из репозитория.

**`.update` пишет «Уже установлена эта версия».** Обновление ставится, только если версия в архиве строго
новее. Для переустановки той же версии распакуйте файлы вручную (папку `user/` это не затронет).

**После `.update` в терминале «Данные пока лежат по-старому».** Обновление со старой версии выполнял прежний
keeper. Перезапустите `python frx_systemkeeper.py` — данные переедут в `user/` (раздел 3).

**Где видно, что изменилось в версии?** `.changelog`, вкладка changelog на главной сайта, `CHANGELOG.md`.

## 40. Безопасность

- `user/` содержит сессии (вход в аккаунты без пароля), токен бота и ключи нейросетей — не публикуйте и не
  пересылайте её и бэкапы. `.gitignore` уже исключает `user/`.
- `.eval`, модули, WebIDE и инструменты `run_python`/`run_command` исполняют любой код с полным доступом к
  аккаунту и машине. Устанавливайте только модули, код которых прочитали.
- Сайт `.web` — только `127.0.0.1`; не публикуйте его порт наружу, используйте SSH-туннель.
- Код из WebIDE-помощника и диалоги NeuroDash уходят выбранному провайдеру нейросети — для приватного
  используйте локальную модель.
- Автоматизация пользовательского аккаунта может нарушать правила Telegram; не используйте FRX для спама и
  массовых действий.

Что делать при утечке и как сообщить об уязвимости — [`SECURITY.md`](SECURITY.md).

## 41. Участие и лицензия

**Как предложить изменение.** Issue с описанием проблемы (версия из `.info`, шаги, лог из терминала **без
секретов**) или pull request. Для изменений ядра:

- поднимите `FRX_VERSION` в `core/engine.py` и добавьте запись сверху `CHANGELOG.md`
  (`## <версия> — <дата>`, обычный Markdown) — по ней придёт уведомление об обновлении;
- новые пути к данным берите из `core/paths.py`; логику путей keeper'а (`frx_systemkeeper.py`) держите
  согласованной с ним;
- `frx_systemkeeper.py` — только стандартная библиотека и без импортов из `core/`;
- новые команды встроенных модулей добавьте в путеводитель нейросети `core/frx_guide.md` и в этот README;
- проверка без Telegram: `python -m compileall .`, модули — в Sandbox на сайте.
