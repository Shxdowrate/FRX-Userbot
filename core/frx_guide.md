# Краткий путеводитель по FRX (для нейросети NeuroDash)

## Что такое FRX
FRX — Fractal Runtime Extension: Telegram-юзербот на Telethon (работает от имени аккаунта владельца) с параллельным стационарным ботом на aiogram и локальным сайтом управления. Функции даёт система модулей: каждый модуль — один .py-файл с метаданными (NAME, MODULE_NAME, VERSION, AUTHOR, DESCRIPTION) и обработчиками (команды, наблюдатели за сообщениями, события, циклы, инлайн-формы, конфиги). Запускается через frx_systemkeeper.py: он держит процесс, умеет перезапуск, обновление и бэкапы.

## Команды
Команды пишет владелец в любом чате, с префиксом (по умолчанию «.»).
- .help (.h) и .modules (.mods) — список модулей и карточка модуля; .help <модуль> — сразу карточка.
- .loadmod (.lm) — загрузка модуля ответом (reply) на .py-файл; .unloadmod (.ulm) — выгрузка; .reloadmod (.rm) — перезагрузка; .restoremods (.rsm) — вернуть выгруженные; .sendmodule (.sm) — прислать файл модуля.
- .config (.cfg) — настройки модулей: сначала «встроенные / загруженные», потом модуль; .cfg <модуль> — сразу его настройки. .confighelp — подсказка.
- .info — версия ядра, аптайм, система. .changelog (.cl) — что нового в обновлениях.
- .update (.upd) — обновление ядра из zip; .restart (.rs) — перезапуск; .exit — выключение; .sk — меню SystemKeeper (бэкапы, восстановление).
- .logs — просмотр логов; .ping, .dping — задержка; .eval / .ev — выполнить Python-код (опасно, только владелец).
- .web (.site) — сайт управления, в чате — инлайн-панель (запуск/выключение, вход, публичный адрес, автозапуск);  ссылки приходят в ЛС от бота; вход на сайт закрыт, пока не напишешь .web — тогда приходит 5-значный код (вход открыт 10 минут для одного устройства) или кнопка «Открыть в Telegram»; .web tunnel on — публичный адрес https://….trycloudflare.com (открыть откуда угодно); .web logout — выйти везде.
- .accounts (.acc) — аккаунты; .botchat (.bc) — чат со стационарным ботом; .forms, .closeform — инлайн-формы.
- .neuro (.n) — нейросеть NeuroDash (диалог); .neurotool (.nt) — инструменты нейросети.
- .access (.acs) — доступ других людей к командам юзербота: ответом на сообщение человека — меню «Выдать доступ» (класс или разрешение на модуль / команду) и «Отозвать доступ»; текстом .access grant|revoke|check [пользователь] <что>, .access list. Классы (FULL, LOADED, свои с idn/названием/описанием) — на сайте, вкладка «доступ». Опасные модули помечены ⚠.
- .alias <команда> [аргументы] <новое_имя> — свой алиас команды (.alias help h2, .alias config helper cs); .alias — список; .unalias <имя> — удалить. На сайте — внизу вкладки «конфиги».

## Модули
Встроенные лежат в modules/builtin (идут с обновлением, выгрузить нельзя), пользовательские — в user/modules; выгруженные уезжают в user/modules/unloaded. NeuroDash — встроенный модуль. Список реальных модулей и их команды лучше брать инструментом list_modules.

## Сайт .web
Сайт управления юзерботом (127.0.0.1; с другого компьютера — SSH-туннель или публичный адрес .web tunnel on; вход по коду из Telegram): главная с панелью, список модулей, WebIDE — редактор и конструкции для написания модулей без ручного кода, Sandbox — проверка кода, Emulate — рисует команды, формы и диалоги модуля, вкладка neuro — ключи провайдеров, модели, планы токенов, инструменты и настройки нейросети, логи, активные задачи.

## NeuroDash и инструменты
NeuroDash отвечает нейросетью (любой провайдер с ключом: выбор «провайдер → модель»), считает расход токенов, умеет вызывать инструменты — файлы в user/data/neuro/tools/<категория>/<имя>.py. Категории открываются по ключевым словам или вызовом open_category. Опасные инструменты (run_python, send_message, delete_file) просят подтверждение кнопками. Нейросеть может выполнять команды юзербота инструментом run_command (с аргументами; перед каждым запуском просит подтверждение; выключение, обновление, eval и сама нейросеть запрещены). «Тяжёлые» инструменты (много токенов, например полный README) тоже просят разрешение. Управление: .nt (меню), .nt add (ответом на код), .nt on|off <имя|категория>, .nt send <имя>, .nt del <имя>.

## Обновление и версии
.update принимает zip обновления (корневая папка FRX/). Перед обновлением keeper делает бэкап. Записи об изменениях — CHANGELOG.md и .changelog. Подробная техническая документация для разработчиков модулей — README.md (инструмент frx_help ищет и там).
